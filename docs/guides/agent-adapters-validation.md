## 实际运行

- 通过官方 `@opencode/client` 的服务发现和认证连接真实 OpenCode 服务，运行现有生产插件的 `setup` 和新的投递适配器。一次订阅观察到 103 条公共事件；经现有语义映射与桥投递，游戏持久记录 1 次真实工具工作，桥待投递队列归零。公共流更新数不作为工作次数。
- 首次投递暴露出 Store 补默认字段但未标记 dirty 的基线问题。修正为工作事务前强制保存完整基线后，原失败 WAL 在 Store 打开前恢复，未重置存档或删除事务文件。
- 将同一已观测事件提交到独立的新游戏存档，首次返回 `applied`，再次返回 `duplicate`；关闭并重新打开运行时后仍返回 `duplicate`，持久工具计数保持 1。
- 重启后的本机接口重复投递返回 `200 / duplicate`，工具计数保持 1；未认证健康查询返回 `401`。
- Windows 原生 Electron 使用同一通用运行时的后台线程，接收同一实际事件，返回 `applied`，退出后存档工具计数为 1。原截图入口完成收起状态、打开面板和两张截图，进程正常以 0 退出。

## DSH 桌面实机

使用已安装的 DeepSeek Harness Desktop `0.2.0-rc.2`，通过其自带 `dsh plugin --profile desktop add <原型目录>` 加载本分支。`DSH_HOME` 与 Electron `--user-data-dir` 均指向独立临时目录，原配置、会话和小猪存档不参与运行。

- 原生 DSH 窗口显示小猪，展开状态面板正常；在聊天输入框执行 `/pig hatch`，真实命令服务返回孵化结果并创建存档。
- 提交一条无凭据消息，宿主产生 `MISSING_CREDENTIAL`，游戏记录 1 次 `message` 和 1 次 `agentError`。
- 经用户允许，仅复用原 DSH 的模型凭据引用。提交一个只读文件任务，实际工具完成后回复 `DSH_PIGGY_OK`；游戏再记录 1 次 `message`、1 次 `tool` 和 1 次 `turn`。
- 最终持久计数为消息 2、工具 1、成功回合 1、Agent 错误 1；对应 5 个来源为 `dsh` 的收据，没有遗留 WAL。
- 正常退出后移除临时凭据，再重新打开同一隔离存档：界面挂载正常，游戏状态路由返回 `200`，上述计数和收据保持不变；退出均为 0。

没有人工发射 DSH 事件或直接调用适配器来代替实机工作。本轮没有触发真实 `toolError`，该分支仍由已有宿主检查覆盖；也没有做 Linux、macOS、断电或高负载验收。
