# 动效、渲染、手绘和配色：先用成熟的库和做法，别自己造轮子

做动画、手感、粒子、特效之前读这一份。用户希望猪和界面「灵动」，也希望接手的 agent **先参考 Motion、GSAP、PixiJS、Three.js、Rough.js、mo.js 这些成熟项目**，
而不是自己从头写缓动、弹簧、时间轴、粒子系统；配色、渐变、对比度这类颜色计算同样先用 Chroma.js 这样的成熟库。

两种「参考」都算：
- **引进来用**：把库打进游戏包（要守下面的许可、体积、性能规矩）；
- **学它的做法**：读它的文档、示例、源码，学节奏、缓动、弹簧参数、粒子的思路，用浏览器自带的能力（CSS、Web Animations）实现。

> 什么时候都不该做的：自己手写一个缓动函数库、一个弹簧求解器、一个时间轴调度器、一个粒子引擎、一套颜色空间转换。这些成熟库都有，而且调得比我们好。

---

## 1. 四个项目一览（2026-10-08 核对）

| 项目 | 许可 | 版本 | 打进游戏包增加多少（esbuild 压缩 / 再 gzip） | 在本项目的定位 |
|---|---|---|---|---|
| [Motion](https://motion.dev)（`motion`，原 Framer Motion 的通用版） | **MIT** | 14.0.0 | `motion/mini` 的 `animate`：**9KB / 4KB**；完整版 `animate`+`spring`+`stagger`：**59KB / 22KB** | **首选**：面板、按钮、猪的弹跳 / 挤压 / 弹簧手感 |
| [GSAP](https://gsap.com) | **不是开源许可**（GSAP 自己的「免费标准许可」，版权归 Webflow，可随时修改条款、可撤销） | 3.15.0 | 70KB / 28KB | **不引进来**；只当学习和设计节奏的参考 |
| [PixiJS](https://pixijs.com) | **MIT** | 8.22.0 | 516KB / 150KB | 很多精灵 / 粒子的 2D 场景才考虑；猪本身不用 |
| [Three.js](https://threejs.org) | **MIT** | 0.186.1 | 518KB / 131KB | 3D；和现在的平面猪风格不搭，特殊玩法才考虑 |
| [Rough.js](https://roughjs.com) | **MIT** | 4.6.6（2024 年后少有更新，功能稳定） | 27KB / 9KB | **手绘风**：草图线条、手绘填充，给猪周围加涂鸦感的点缀 |
| [mo.js](https://mojs.github.io)（`@mojs/core`） | **MIT** | 1.7.1 | 118KB / 32KB | **爆点和形状动效**：摸猪冒的心、升级、拆礼包时的放射、圆圈扩散、彩带 |
| [Chroma.js](https://gka.github.io/chroma.js/) | **BSD-3-Clause + Apache 2.0**（都是宽松开源许可，要保留版权声明） | 3.2.0 | 45KB / 18KB（按需引入也减不下来） | **配色计算**：调色板、渐变、颜色混合、对比度检查；优先在工具和测试里用 |

[开发新功能](adding-features.md) 规定游戏包整体增加超过 300KB 要在设计稿里说明。）

## 2. 怎么选（从轻到重）

1. **CSS 动画 / 过渡**：小动作、悬停、开关面板的淡入，项目里已经大量这么做（`css-*.js` 里的关键帧、`data-react` / `data-idle` 属性）。
2. **Web Animations API**（`element.animate()`）：需要用 JS 控制、能中途取消的短动画，项目已有 `src/client/interaction-motion.js`。
3. **Motion / mo.js / Rough.js**：Motion 管**弹簧手感**和元素运动；mo.js 管冒出来的爆点特效；Rough.js 管手绘风点缀。Motion 需要**弹簧手感**（猪被摸时 Q 弹、落地回弹）、**连贯的多段编排**（一串依次出现、跟手拖动后的惯性回弹）时用。
   它底层就是 Web Animations，体积小、MIT，和项目最搭。
4. **PixiJS**：一屏几十上百个会动的东西（下雨、满屏金币、钓鱼的水波和鱼群、小游戏场景），DOM 撑不住时才考虑。
5. **Three.js**：真的需要 3D 时。现在的美术是平涂 2D，基本用不到。

**选之前先问**：这个效果用 1、2 做得出来吗？做得出来就不要引库。引库要在设计稿里写清「为什么 1、2 不够」。

## 3. 各自怎么用、要注意什么

### Motion（首选）

- 可以直接用来做：弹簧（`type: 'spring'`，参数 `stiffness` / `damping` / `bounce`）、依次出现（`stagger`）、多段编排、打断当前动画接新动画。
- 先用 `motion/mini`（只有 `animate`，4KB gzip），不够再换完整版。
- 只在面板这一层（`src/client/`）用，领域层和宿主不碰。
- **想要 Q 弹的手感，先调 Motion 的弹簧参数，别自己写物理公式。**

### GSAP（只参考，不引进来）

- 不引进来的原因：它不是开源许可，版权方可以随时改条款、可以撤销授权；本项目是 MIT 开源，玩家和下游再分发时会被卷进一份我们控制不了的条款里。
- 能学的：它的文档和示例是业界最好的动画教材之一——
  [缓动可视化工具](https://gsap.com/docs/v3/Eases/)（选节奏、对比曲线手感）、时间轴编排的思路、MotionPath（沿路径走）、MorphSVG（形状变形）的效果示例。
  学到的节奏用 CSS / Web Animations / Motion 实现。
- 如果以后真有非它不可的效果，先问用户、说清许可风险，用户同意才引入。

### PixiJS（重型 2D，谨慎）

- 适合：大量精灵、粒子、精灵图（sprite sheet）动画、需要滤镜特效的独立场景。
- 不适合：猪本身和面板（那是 SVG + DOM，换渲染方式会和现有的形状测量、可点区域、皮肤系统全部打架）。
- 体积大：只能在**独立的场景页**里按需加载，不能打进主包常驻。在线扩展单个文件上限 512KB，也装不下它——真要用要先出设计（比如由宿主按需提供）。
- 用 GPU（WebGL / WebGPU）：桌面版要考虑**没有显卡的机器**（虚拟机、老电脑）会退回软件渲染、可能很卡，要有降级方案并在无显卡的虚拟机上实测。

### Three.js（3D，基本不用）

- 和平涂 2D 的美术风格不搭；体积和 GPU 问题同 PixiJS。
- 能学的：[官方示例](https://threejs.org/examples/) 里的光影、粒子、着色器思路，可以启发 2D 特效的做法。

### Rough.js（手绘风）

- 适合：手绘感的点缀——气泡和高亮的草图描边、速度线、强调用的圈圈、涂鸦式装饰，让猪和界面多一点「手画的」活泼感。
- **一定要给固定的随机种子**（`seed` 选项）：它每次画都会随机抖动，不固定种子的话每次重画形状都在变，看起来像在闪。
- 能提前算好的（固定形状的装饰）**在开发时生成成 SVG 路径**放进素材，运行时不用再算；只有跟着内容变的（比如包住不同长度文字的气泡）才在运行时画。
- 猪本身的立绘仍按画猪图规范是平涂的；Rough.js 只用在点缀上，不把猪描成草图风（要改整体画风先问用户）。

### mo.js（爆点和形状动效）

- 适合：一次性的「砰」一下——放射线、圆圈扩散、星星四散、彩带，配合摸猪、喂食、升级、拆礼包、成就解锁这些时刻。
- 和 Motion 的分工：**元素本身怎么动（猪弹一下、面板滑出）用 Motion；凭空冒出来的装饰性特效用 mo.js。**
- 规矩：播完把它创建的节点清掉；同一时刻别叠太多（连点时限流）；`prefers-reduced-motion` 时不播；
  桌面版特效只能在猪窗口的固定框里（`measure.js`），飘出框会被裁。
- 现在项目里的爆点是 `effects.js` 的 `burst()`（冒 emoji），先看它够不够；要换成 mo.js 做更丰富的效果，在设计稿里写明替换哪些。

### Chroma.js（配色计算）

- 适合：
  - **生成和调色板**：给「千奇百怪的小猪」做换色方案（同一套猪色板按主题平移色相、保持明暗关系）、给新皮肤配和现有 `--ac-*` 协调的颜色；
  - **渐变和混色**：在 LAB / OKLCH 这类感知均匀的颜色空间里插值（比直接在 RGB 里插值自然，不会中间发灰）；
  - **对比度检查**：算文字和底色的对比度，写成测试守住界面可读性（深色主题、扩展页面的配色）。
- **优先在开发工具和测试里用**（`tools/`、`test/`，放 `devDependencies`，不进游戏包）：配色是设计时算好、写进设计变量的，运行时一般不用再算。
- 运行时真要动态算颜色（比如猪的颜色随健康度渐变），先用浏览器自带的 CSS `color-mix()`、`oklch()`（Electron 和现代浏览器都支持）；
  不够用才把 Chroma.js 打进游戏包（+18KB gzip），并按下面第 4 节记许可。

## 4. 后续思路（先记下，不做）

- **猪被绳子吊着晃**（用户 2026-10-08 提的）：用 **XPBD**（扩展的基于位置的动力学，适合绳子、布料这类约束模拟，稳定、好调）做绳子，
  猪挂在绳子末端随拖动和惯性摆动。到时候先出设计稿：用现成的物理库还是自己按论文写一个小求解器（绳子只需要距离约束，代码量不大）、
  在猪窗口固定大小里怎么放下摆动范围、怎么关掉。**现在不做。**

## 5. 不管用哪个，都要守的

- **以本项目为准**：这些库的默认样式、示例里的做法和本项目的规范（`--ac-*` 配色、猪的画风、面板要简洁）冲突时，一律以本项目现状为准。
- **许可**：只引进 MIT / BSD / Apache 2.0 这类宽松开源许可的库；写进 `THIRD-PARTY.md`（名字、版本、许可、用在哪），BSD / Apache 的要随包附上版权声明。
- **版本钉死**：`package.json` 里写确切版本；它由 esbuild 打进 `client.js`，所以放 `devDependencies`，同时更新 `docs/DEVELOPMENT.md` 和发版工作流里的安装命令。
- **体积**：引入前后各量一次 `client.js` 和游戏包大小，写进设计稿和提交说明。
- **减少动态效果**：系统设置了 `prefers-reduced-motion` 时关掉或换成不动的（Motion 的动画也要判断）。
- **不常驻跑帧**：动画播完就停；猪闲着时不能有每帧都在跑的循环（桌面版常驻，耗电、占 CPU）。页面不可见时暂停。
- **桌面版窗口**：动画只在猪窗口里面动，**不能改窗口大小**；伸出去的效果在 `src/client/desktop/measure.js` 的固定框里留位置（见 [桌面架构](desktop-architecture.md)）。
- **两个窗口不重复演**：猪的动作只在猪窗口演（见 [开发新功能](adding-features.md) 3.2）。
- **验收**：真实浏览器和桌面版里看；会动的东西录屏逐帧看有没有跳帧、闪一下；无显卡虚拟机上看会不会卡。
