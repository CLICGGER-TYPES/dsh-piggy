# 给猪加台词

「语音」在这个项目里就是**猪头上的气泡台词**（项目没有音频）。台词是内容，**写什么、写多少由用户拍板**：
新台词先出审稿单给用户看，用户说「按稿上」才进代码（历史稿：`docs/tasks/numbers/B6-lines.md`、`G4-lines.md`）。

## 台词放在哪

| 位置 | 是什么 |
|---|---|
| `packages/pet-core/src/data/lines.js` | 最早的一批场景（B6）和类型定义；`LINES` 是**所有场景的总表**（把下面这份并进来） |
| `packages/pet-core/src/data/lines-more.js` | 之后加的句子和新场景（`MORE_LINES`），以及按时间说话的表：时段 `TALK_SLOTS`、节日 `SOLAR_HOLIDAYS` / `DATED_HOLIDAYS`、摸部位 `PET_PARTS` |
| `packages/pet-core/src/core/lines.js` | 规则：挑哪句（最近 3 句不重复）、换称呼、口头禅、回复按钮加心情 |
| `packages/pet-core/src/core/talk.js` | 按时间说话的规则（时段问候、喝水/护眼提醒、节日、生日） |

**新台词一律加在 `lines-more.js`**（加进已有场景的数组，或新开一个场景）。

> 面板里还有几处写死的短句不是「猪的台词」，而是操作反馈：`src/client/constants.js` 的 `BOX_POKE_LINES`（拆纸盒）、
> `NO_ITEM_LINE`（背包空了）、`src/client/io.js` 的失败原因、`src/client/effects.js` 的 `REACTIONS.say`（只在宿主不说话的动作上冒）。
> 改这些也要用户同意，但它们不走场景表。

## 一句台词长什么样

```js
line('今天的饭有[主人]的味道（是夸你）')          // 只有文字
line('这个好吃，下次还要这个', '记住了')           // 带一个回复按钮：主人点了加心情（每句只算一次）
```

- **`[主人]`** 是唯一的占位符，换成玩家设的称呼（默认「主人」，最长 12 个字）。别发明别的占位符。
- **`（…）`** 全角括号写动作或心里话，比如「（眯起眼睛）」。整句以括号开头或结尾时不会被加口头禅。
- **长度**：每句 ≤ 30 个字（`[主人]` 按 2 个字算），回复按钮 ≤ 8 个字。气泡最多两行，太长会被截掉。
- **每个场景至少两句**（一年一次的节日、生日除外），不然会一直重复同一句。
- **口头禅**：玩家设了口头禅，猪会随机（40%）在句尾加上，严肃场景（`SERIOUS_SCENES`：去世、生病、吃错药）不加。写台词时不用管。

## 文风

照 QQ 宠物 + 动森村民的说话方式：**短、口语、有点贱萌，可以带一点黑色幽默**；像一只有脾气的小猪在跟主人说话，
不是系统提示。不说教、不用网络烂梗、不写「亲」「宝子」这类客服腔；节日和严肃场景收着点。

## 场景怎么被触发

- 领域层在动作做完时调 `say(state, '<场景>', nowMs)`（如 `care.js` 喂完说 `eat`），闲着时 `chat()` 按优先级挑
  （饿 → 脏 → 孤单 → 闲聊），按时间的由 `talk.js` 挑。
- **新开一个场景** = 在 `MORE_LINES` 加 `<场景名>: scene(line(...), line(...))` + 在领域层合适的地方 `say(state, '<场景名>', nowMs)`。
  场景名用 camelCase 英文。
- 调试 App（版本号上连点 7 下）的「💬 说一句」能直接让猪说任一场景；想在那里显示中文名，顺手在 `src/client/tabs/dev.js` 的 `SCENE_NAMES` 加一项（不加就显示英文名）。

## 写错了会怎样（测试兜底）

`npm test` 会拦下这些（`test/lines-guard.test.js`、`test/helpers/strict-lines.js`）：

- 代码里 `say()` 点名的场景、时段/节日/摸部位表里的场景，台词表里没有 → 红。测试里走到任何未知场景直接抛错。
- 超长、用了别的占位符、场景只有一句 → 红。
- 农历节日表要逐年连续。**`DATED_HOLIDAYS` 目前写到 2029 年**，2029 年内要续上后面几年（农历日期用 `lunardate` 之类的库算，清明按节气）。

正式运行时未知场景只是不说话，不会崩——所以这些错只有测试能发现，**加台词后必须跑 `npm test`**。

## 加完之后

1. `npm run build && npm test`。
2. 在调试 App 里让猪说几句新台词，看气泡里显示是否完整（两行内、没被截）。
3. CHANGELOG 写一句「新增 N 句台词 / 新场景 X」。
4. 不用升存档版本（台词不进存档；`dialogue.lastByScene` 按下标记，加句子不影响旧存档）。
