# 开发新功能：流程、放哪、预留的扩展点

给接手的 DeepSeek / codex / 开发者。加任何「玩家能感觉到」的东西——新玩法、音效、动作动画、猪走路、动图、联网功能——都按这一份走。
这里不规定具体做成什么样（那要用户定），只规定**怎么定、放哪、守什么规矩、怎么验收**，免得各写各的。

先读 [AGENTS.md](../../AGENTS.md) 的红线。和本文相关的专项指南：[写扩展](writing-extensions.md)、[加台词](adding-lines.md)、
[加成就](adding-achievements.md)、[界面规范](ui-style.md)、[桌面架构](desktop-architecture.md)、[画猪图](../design/pig-kitchen-art.md)。

---

## 1. 流程（每个新功能都走，不能跳）

1. **问清需求**：用户的例子往往只是举例。先复述你理解的范围，有分歧的点一次问清（别一步一问）。
2. **先查 [参考项目总表](references.md)** 有没有相关的项目可以借鉴；再**写设计稿** `docs/design/<功能名>.md`（模板见第 6 节），**用户确认后才写代码**。大功能一次设计完整，不「先做一半、留个口子」。
3. **数值、文案、台词、图、音效**：单独出确认单（数值放 `docs/numbers/`），用户确认过的不改。
4. **在分支上做**：`feat/<功能名>`，多人同时做用 `git worktree`；做完合回 main 删分支。
5. **测试**：先写失败测试再实现；`npm run build && npm test && npm run typecheck` 全绿。
6. **真实验收**：网页版在真实浏览器里看；桌面版两个平台真机看（窗口、拖动相关的要真鼠标 + 录屏，见桌面架构「怎么验收」）。
7. **给用户验收**：出测试版（`x.y.z-rc.N`），一批改完只出一个；用户说通过才发正式版。
8. **收尾**：CHANGELOG、README（文字和截图）、玩家文档、本目录的相关指南一起更新。

## 2. 先判断放哪

| 这个功能… | 放哪 | 要点 |
|---|---|---|
| 只影响**这台设备上怎么显示 / 怎么提醒**（音效开关、动画、猪的大小、散步） | 面板 `src/client/` + 本机设置（localStorage） | 不进存档，不影响 DSH 和桌面两边的猪 |
| 改**养成规则**、要**存进档**（新属性、新状态、新物品） | `packages/pet-core/src/data/` 数值 + `core/` 规则 + 组装层路由 + 面板 | 守分层；存档加字段见第 3.4 节 |
| **一整块能单独开关的玩法**（像菜园、矿洞） | **优先做在线扩展**（`extensions/<key>/`）；要改核心规则才做成内置扩展 | 在线扩展不用发游戏版本就能上线、出错只影响自己 |
| 需要**桌面程序的新能力**（新窗口行为、系统托盘、全局快捷键） | 外壳 `apps/desktop/` + 游戏包里做兼容判断 | 升外壳版本；见桌面架构「分工」 |
| **图、音、字体**等资源 | `assets/` 下按类别分子目录 | 许可和出处见第 3.5 节 |

拿不准就在设计稿里把两种放法的利弊写出来让用户选。

## 3. 通用规定

### 3.1 能关、尊重免打扰

- **主动打扰玩家的东西都要有开关**（会响、会动、会走、会弹出来的）。默认开还是关由用户定，设计稿里写明。
- 开关放「设置」里（`src/client/tabs/settings.js` 的 `section()`），一个功能一节，标题 + 一句说明，照现有「桌面散步」那节写。
- 本机设置的键名统一 `dsh-piggy:<功能名>`（kebab-case），读写一律经 `src/client/storage.js` 的 `readStore` / `writeStore`（隐私模式、存不下时不出错）。
- **免打扰**（存档 `dialogue.quiet`）开着时：不主动说话、不报日常消息、不散步——新功能同样要听它（生病、去世这类紧急的除外）。
- 系统「减少动态效果」（`prefers-reduced-motion`）打开时，动画要关掉或换成不动的。

### 3.2 两种形态都要能跑

- 同一份游戏包跑在 **DSH 网页面板**和**桌面版两个窗口**里。新功能三处都要想到：网页、桌面猪窗口、桌面面板窗口。
- 只有桌面能做的（比如窗口外走动），网页版要**安静地不做**，不能报错；用 `desktopShell()` / `desktopRole()`（`src/client/desktop-shell.js`）判断，
  用外壳新能力前先 `typeof shell.xxx === 'function'`。
- 拆窗口后同一件事两个窗口都会收到：**猪的表现（动作、气泡、声音）只在猪窗口做，提示条只在面板窗口出**（见 `src/client/pending.js`），不然演两遍。

### 3.3 时间、随机、计时器

- 领域层（`core/`）不读时钟、不用 `Math.random()`：时间当参数传，随机用 `core/random.js`。
- 面板里的计时：闲着的时候不要跑 `requestAnimationFrame` 循环或高频定时器（桌面版常驻，耗电）；动画用 CSS / Web Animations，播完就停。
- **位置、尺寸、计数一律从源头重新算，不在上一轮结果上累加**——本项目最常见的 bug（面板越跑越远、猪越用越偏都是这个）。

### 3.4 存档

- 加字段：用 `ensureXxx(state)` 补默认值，**不升存档版本**；改结构（改名、拆字段、换类型）才在 `core/upgrades.js` 加一级 + `STATE_VERSION` +1 + 迁移测试。
- 旧存档必须能自动迁移，不丢数据。功能关掉、扩展卸载后，玩家的进度怎么处理要在设计稿里写明（一般是保留）。

### 3.5 资源（图、音、字体、动图）

- **许可**：只用自己做的、AI 生成且不侵权的（规则同 [画猪图](../design/pig-kitchen-art.md) 第 2 节）、或 CC0 / MIT / Apache 2.0 这类宽松许可的。
  CC-BY 要署名、CC BY-SA 会传染、「仅个人使用」「免版税但不可再分发」的一律不用。每个第三方资源写进 `THIRD-PARTY.md`；
  AI 生成的在资源目录放 `PROVENANCE.md` 记工具、条款、提示词。
- **图可以直接用 AI 出**（用户 2026-10-09 确认）：立绘、动作图、图标、插图都可以直接用 agent 自带的生图工具（如 codex 的 `image_gen`）出，
  不用先手画，也不用再描成 SVG。交位图时：
  - **透明底 PNG**，白底/纯色底在出图后离线抠掉（Pillow 等），不要靠 CSS 滤镜、`mix-blend-mode` 在运行时去底——桌面外壳会盖掉这些样式，抠白也会伤到图里的白色；
  - **缩到实际显示尺寸的 2 倍左右**（猪立绘一般长边 ≤ 256px），单张尽量 ≤ 60KB；原图留在工作区，不进仓库（参照 `assets/PROVENANCE.md` 的睡姿图）；
  - 许可规则同 [画猪图](../design/pig-kitchen-art.md) 第 2 节（不写商标/角色/画师名，参考图只用本项目自己的图），`PROVENANCE.md` 记工具、提示词、参考图；
  - 仍然要**用户过目确认**才进 `assets/`。
- **用户确认**：新的图、音效、动图要先给用户看 / 听，确认后才进 `assets/`。
- **体积**：游戏包（`game-*.json.gz`）现在约 1.4MB、`client.js` 约 430KB，玩家每次热更新都要下载。资源单个尽量小（下面各节有上限），
  新功能整体让游戏包增加超过 300KB 要在设计稿里说明。Gitee 的 Windows 安装包离 100MiB 上限只剩约 6MiB（0.6.1），**大资源不要塞进外壳**。

### 3.6 联网

- 不新增对第三方服务的请求，除非用户同意（设计稿里写清连哪、发什么、失败怎么办）。不上传玩家数据。
- 地址走发布渠道（`channel.js`：GitHub / Gitee 两套），**Gitee 渠道不能依赖 GitHub**。
- 请求由宿主（Node 端）发、带超时和重试，失败要在界面上说清楚，不能卡住或静默失败（参考扩展下载 `store/ext-runtime.js`）。

## 4. 预留的扩展点

这些是「以后很可能要加、现在先把规矩定好」的方向。**具体做不做、做成什么样由用户定**；这里写的是做的时候该放哪、守什么。

### 4.1 新玩法 / 新 App

- 能独立开关的整块玩法 → 在线扩展（[写扩展](writing-extensions.md)）。
- 改核心的（新属性、新状态、新外出类型）→ 数值进 `data/`、规则进 `core/`，面板加 App 页（`src/client/tabs/<名字>.js`，在 `TABS` 里登记，主菜单图标用 emoji）。
  界面先用现成组件；没有的照动森 UI 设计系统（animal-island-ui）的规格做，见 [界面规范](ui-style.md)「动森 UI 设计系统」。
- 配套要想到的：猪说什么（[加台词](adding-lines.md)）、有没有成就（[加成就](adding-achievements.md)）、图鉴要不要收、免打扰时怎么办、关掉 / 卸载后数据怎么办。

### 4.2 音效（现在没有，预留）

- **一个入口**：新建 `src/client/sound.js`，只暴露 `playSound(key)`；其它代码只调它，不直接 `new Audio()`。
- **事件 → 声音的表**放一个地方（如 `src/client/sounds.js` 的 `SOUNDS = { feed: 'eat', levelup: 'levelup', … }`），声音文件 `assets/sounds/<key>.ogg`（Opus 编码，Chromium / Electron 都能播）。
- 规矩：
  - 设置里「音效」一节：开关 + 音量（三档即可）；默认开关由用户定；**免打扰时不响**（紧急事件可以例外，设计稿里写明）。
  - **只在猪窗口播**（拆窗口后两个窗口都会处理同一件事，见 3.2）；网页版遵守浏览器「先有点击才能出声」，第一次没声音不报错。
  - 单个 ≤ 30KB、全部 ≤ 500KB；短（≤ 1.5 秒），不循环背景音乐（要背景音乐另立设计）。
  - 核心和宿主不碰声音；在线扩展暂不允许带声音（以后要开再给扩展 api 加 `api.sound(key)` 之类，只能播宿主已有的声音）。
- 验收：开关和音量真的生效、免打扰时不响、两个窗口不重复响、连续快速操作不叠成一片（同一个声音正在播就不重复起播）。

### 4.3 动作和动画（现有机制）

- **立绘按场景切换**：每套立绘有 `idle` 和动作场景（`eat`、`bathe`、`play`、`pet`、`relaxed`、`work`、`study`、`trip`、`fish`、`sleep`，见 `data/skins.js` 的 `SKIN_SCENES`），
  一般文件名是 `<立绘>-<场景>.svg`，缺的动作图回退到 `idle`。睡姿单独处理：内置形态用 `*-sleep.png`，自定义皮肤可提供 `sleep.svg`，缺少时用默认小猪睡姿。切换逻辑在 `src/client/art.js`。
- **加一个新动作场景**：在 `SKIN_SCENES` 末尾加（可选场景，不进必需列表）→ `art.js` 里接上触发 → 皮肤包格式文档同步 → 现有皮肤缺这张就回退，不强制补画。
- **小动作和反应**用 CSS（`data-idle`、`data-react` 属性 + `css-*.js` 里的关键帧）；短的界面反馈用 `src/client/interaction-motion.js`。
- **要更灵动的手感（弹簧、回弹、编排）**：先用成熟的库和做法，不要自己写缓动、弹簧、粒子——见 [动效和渲染库](motion-libraries.md)（首选 Motion，GSAP 只参考不引入）。
- **逐帧动画**（以后要更细的动作时）：文件名 `<立绘>-<场景>-f<序号>.svg`（`f1`、`f2`……），帧率 ≤ 12 帧/秒，用 CSS `steps()` 或定时换 `src`，
  缺帧就退回静态的 `<立绘>-<场景>.svg`。每帧照画猪图规范（64×64、和 `piglet.svg` 对齐，帧和帧之间脚底不跳）。
- **桌面版的硬约束**：动画只能在猪窗口**里面**动，**不能改猪窗口大小**（改一次就闪一帧，见桌面架构第 3 条）；会伸出去的东西（飘的爱心、道具）
  要在 `src/client/desktop/measure.js` 的固定框里留好位置。

### 4.4 猪走路 / 移动（现有：桌面散步，默认关）

- 现状：`src/client/life.js` 的 `walk()`，设置里打开后每 10～20 分钟沿屏幕底边走一段再走回来；拖动、开着面板、免打扰时不走。
- 规矩：
  - **按「起点 + 第几步」算位置，不要一步步累加挪动**。现在的 `walk()` 是连续调 `moveBy(±2)`，走的距离会被系统取整误差带偏——
    改动走路时顺手改成「每一步都从起点算目标位置」，走完按真实落点 `placement.rehome()`（见 `src/client/desktop/place.js` 的「家」模型）。
  - 走路时猪的朝向（`data-walk="left|right"`）和走路立绘（如果以后有 `-walk` 场景 / 帧）跟着方向换。
  - 不走出屏幕：每一步都夹在当前屏幕工作区里；多显示器时只在当前屏上走。
  - 用户一拖、一开面板、一开免打扰，立刻停下并按当时位置定家。
  - 网页版里走路只在面板所在的页面区域内，或者干脆不走（设计稿里定）。
- 验收：Linux + Windows（含 125% 缩放）真机录屏，走完回到的位置和出发点差 ≤ 2px，走的过程中不闪、不跳。

### 4.5 动图（GIF 等）

- **游戏自带的素材不用 GIF**：位图、文件大、半透明边缘难看、放大会糊。要动的效果用 4.3 的 SVG 逐帧或 CSS。
- **玩家导入的自定义皮肤**如果以后要支持动图：先出设计稿，改皮肤包格式（`docs/guides/skin-pack-format.md`）并给格式加版本号；
  优先支持「SVG 逐帧」，位图动图优先 APNG / 动态 WebP（支持透明），GIF 最后考虑；单张大小、帧数、总时长都要设上限，
  导入时照现有 SVG 皮肤那样做安全清洗（不许脚本、外部引用）。

### 4.6 设置项

- 一项设置 = 设置页一节（标题 + 一句说明 + 开关 / 分段选择），不加长段说明（面板要简洁）。
- 只影响这台设备的放 localStorage（3.1）；影响玩法、两边要一致的放存档（走路由动作，如免打扰的 `setQuiet`）。

### 4.7 桌面外壳的新能力

- 先确认游戏包里做不到，再动外壳；新 IPC 消息照 [桌面架构](desktop-architecture.md) 的表登记，处理函数里核对是哪个窗口发的。
- 外壳升版本；游戏包用新能力前判断外壳有没有；需要时提高 `minShell`。

### 4.8 按时间 / 外部数据的功能（如现实作息、城市天气）

- 已有设计待用户拍板：`docs/archive/tasks/E-round.md`。做之前先读它。
- 时间按玩家本地时间；外部数据（天气）按 3.6 联网规定，拿不到时功能自动隐身，不影响其它玩法。

## 5. 完工检查清单（交给用户验收前自己过一遍）

| ☐ | 检查 |
|---|---|
| ☐ | 设计稿用户确认过；数值 / 文案 / 图 / 声音都确认过 |
| ☐ | 有开关（会打扰人的功能）、听免打扰、听「减少动态效果」 |
| ☐ | 网页版、桌面猪窗口、桌面面板窗口都试过，没有重复执行、没有报错 |
| ☐ | 没有在上一轮结果上累加的位置 / 尺寸 / 计数 |
| ☐ | 旧存档能打开、新字段有默认值；需要迁移的有迁移测试 |
| ☐ | 新资源有许可记录（`THIRD-PARTY.md` / `PROVENANCE.md`），体积在预算内 |
| ☐ | `npm run build && npm test && npm run typecheck` 全绿；新规则有测试，能静态守住的规矩写成测试 |
| ☐ | 真实浏览器 / 真机看过；桌面窗口相关的真鼠标 + 录屏 |
| ☐ | CHANGELOG、README、玩家文档、相关指南已更新 |

## 6. 设计稿模板（`docs/design/<功能名>.md`）

```markdown
# <功能名>

状态：待确认 / 已确认（日期） / 已上线（版本）

## 1. 要解决什么（用户原话 + 我的理解）
## 2. 玩家看到什么（界面截图或草图、文案）
## 3. 规则和数值（或链到 docs/numbers/ 的确认单）
## 4. 放哪（第 2 节的判断）、改哪些文件
## 5. 开关、免打扰、两种形态、存档（第 3 节逐条回答）
## 6. 资源（图 / 音）的来源和许可
## 7. 不做什么（这次明确不做的，以免被理解成「预留」）
## 8. 测试和验收（自动测试 + 真机怎么看）
## 9. 要用户拍板的问题
```
