> 以及每条验证结论是靠什么证据得出的**。

> 而那些教训（尤其是"什么才算验证过了"）比代码本身更值得留下。

## 轮次 0：调研与第一版

### 调研方法

没有凭印象猜，而是把两个参考仓库翻到源码层：

1. **`qqpet_automation`** —— 拿数值。`src/qq_pet/game_data.py` 里有阈值和完整疾病链，
   `models.py` 里有属性上限和 `ActiveOption { work, study, trip, ill, die }`。
   → 确认了用户记忆里的"打工 / 生病"**确实在原版数据模型里**，
   只是那个自动化工具没去驱动它们。
2. **`ice-cream-headache.github.io`** —— 拿界面。根目录的 `1.png` / `2.png` 是真实截图，
   用 `read_image` 直接看了：蓝天草地 + 企鹅 + 正下方奶油色图标栏 + 带标签的属性条。
3. **`qqpet_automation` 的资源树** —— 拿玩法清单。`img_res/study/` 下的
   `xx-` / `dx-` / `yjs-` 前缀暴露了三学段，9 个科目名直接可读。

> 中间试过 `modlens_read_image`，失败于未配置视觉通路（提示可复用 codex/opencode/pi，
> 但需要用户同意）。没有擅自改配置，改用原生 `read_image`。

## 每一轮改了什么的细节

### 轮次 1 → 动画与按钮

用户说「不会动」。查下来是动画幅度只有 **3px**，肉眼基本看不出来。改成：

- 常态呼吸摇摆 **6px + 2.5° 倾斜**，1.8 秒一轮
- **心情驱动**动画（开心加速 / 困了鼓气 / 饿了抖 / 脏了蒙蜡）
- 每个动作专属 keyframes + 粒子特效

同时把「要敲命令」这条解决掉：面板里放四个动作按钮，
并且**没孵蛋时也有「🥚 孵一只」按钮** —— 从装到养一次键盘都不用碰。

### 轮次 2 → QQ 宠物机制

完全照逆向出来的数据实现：三条疾病链各四期、健康 5 点、
四档对症药、死亡与还魂丹、以及上限随等级的换算说明。

**一个设计决定**：死亡虽然保留（忠于原版），但**等级、经验、金币、收藏全部不丢**，
还魂丹能救回来。原版是永久失去，但一个陪你写代码的伙伴不该那样惩罚人。

### 轮次 3 → UI 重做与两个新系统

用户指出三点，全部承认：

1. **学习和旅行没做** —— 之前只加了打工，`ActiveOption` 里另两项漏了。
   补上 9 门课 × 3 学段 + 4 个旅行目的地 + 智魅武三维 + 纪念品收藏。
2. **数值全是 undefined** —— 见下面的 bug #9，这是最严重的一条。
3. **"还是一个长条框"** —— 布局确实是竖着堆的，没有照原版做图标栏。
   改成：宠物在上 → 六个图标在奶油色栏里 → 内容在图标栏之下。

### 轮次 4 → 去背景

用户：「🐖 不需要背景」。原版有蓝天草地，但那是给企鹅的舞台。
删掉渐变、云、草的 CSS 和元素，猪直接站在卡片上。

## Bug 清单

按发现方式分类，因为**"怎么发现的"比"是什么"更有信息量**。

### 靠端到端冒烟测试发现的（伪造 ctx 跑完整流程）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `/pig hatch` 之后仍显示「猪蛋」 | `hatch()` 建了个 `xp=0` 的蛋，孵完还是蛋 | 新增 `hatchEgg()`，孵出来直接是 Lv.2 小猪崽 |
| 2 | **打工中喂食返回成功** | `{ ...result, ...snapshot() }` 里 snapshot 的 `ok:true` 覆盖了结果的 `ok:false` | 快照在前，判定在后；补回归测试 |

这直接促成了 `test/host.test.js` 的诞生（该文件第一个测试就是 bug #2 的回归）。

### **用户发现的**（我该自己发现的）

| # | 症状 | 我的失职 |
|---|---|---|
| 10 | **满屏 `undefined`、商店空白** | 两层错：① 客户端假设了新字段却**没做防御性默认值**；② 用户刷新后我**没有检查**，是用户回报的 |
| 11 | **收起状态图标栏和猪叠在一起** | 见下。断言的是 `el.hidden === true`（标志位），**没有问浏览器它到底画没画** |
| 12 | **`/dsh-pig/state` 一直 404** | 我装浏览器工具后去看页面才发现的。插件自称激活成功，路由却从未注册 |
| 13 | **展开面板时猪被顶出屏幕** | 猪原来是面板的第一个子元素。展开时它被顶到 452px 卡片的顶端，400px 高的窗口里实测 `top: -24`，只剩两只脚。**我从没在矮窗口下看过** |
| 14 | **验证工具本身是坏的** | 预览台的 `setOpen()` 用 `host.firstElementChild.children[0]` 找场景。我把猪挪成兄弟节点后，那变成了 `dp-content`，于是这个"切换状态"的函数**静默变成空操作** —— 我的前后对比其实在测同一个状态，却报了 `pigMoved: 0` |

**#10 的处理**：

- 引入 `normalize(raw)` —— 客户端的第一道工序，把任何载荷（当前/旧版/截断）
  映射成确定形状。字段缺失 → 合理默认值，永不为 `undefined`。
- 加**版本错配提示**：宿主是旧版时，面板顶部明确写出"重启 dsh 之后才会出现"，
  而不是默默留空。
- 加**回归测试**：喂一个旧版宿主的真实载荷，断言六个标签页的渲染文本里
  **不出现 `undefined` 也不出现 `NaN`**。
- 加**截断载荷测试**：`{pig:{name:'猪猪'}, jobs:'nope', shop:42, inventory:null}`
  这种畸形输入也不能崩。

**#11 的处理 —— 这一条改变了我对"测试通过"的理解**：

CSS 里 `.dp-bar{display:grid}`、`.dp-hud{display:flex}` 与 UA 样式表的
`[hidden]{display:none}` **权重相同**（0,1,0），而我的样式表在后面 → 我的赢。
所以 `hidden` 属性对这两个元素**完全无效**。

于是出现了这个局面：

```
测试      103 个全过（包括"收起时 bar.hidden === true"）
浏览器    图标栏照画不误，和深色猪胶囊叠在一起
```

**因为假 DOM 没有 CSS 引擎。** 断言标志位只能证明我设了标志，
证明不了那个元素不可见。

补的两道防线：

1. **静态守卫测试**：扫描 `client.js`，断言每个被 JS 设 `hidden` 的类都有对应的
   `[hidden]` CSS 规则；同时断言 `.dp-bar` 真的带 `display:grid`
   （即"这个守卫是必要的"这一前提本身也被测了）。
2. **`tools/preview.html`** —— 真实浏览器预览台。伪造 `__ModuleLoader__` 与
   `fetch`，喂一份快照给 `client.js`，不连真实 DSH 就能看到收起/展开和六个页签。
   这个 bug 和 #12 都是靠它看见的。

**#12 的处理**：

```js
// 错的：apply() 时裸调 ctx.get —— 没有顺序保证
export const inject = []
ctx.effect(() => {
  const webServer = ctx.get('webServer')
  if (webServer === undefined) return () => {}   // 静默吞掉
})

// 对的：等依赖就绪
ctx.inject(['webServer'], (webCtx) => { ... })
```

对照出来的三种正确姿势：

| 写法 | 出现在哪 | 为什么能用 |
|---|---|---|
| `ctx.inject(['webServer'], …)` | `client/connection`、`client/modules` | 等依赖就绪才跑 |
| `ctx.get('webServer')` | web-app bundle | 但在 `ctx.inject(['connection'], …)` **里面**调，依赖链保证了顺序 |
| `inject = [..., 'webServer']` | whale-girl | cordis 等它就绪才激活 |
| **`inject = []` + 裸调 `ctx.get`** | **本插件** | ❌ 什么保证都没有 |

**共同点还是那条**：一个"优雅降级"的守卫把真实故障吞掉了。
守卫本身没错，错在**它被放在了没有资格判断"降级是否合理"的位置**。

## 验证方法

这个项目最重要的一条纪律：**区分"看起来对了"和"验证过了"**。

### 三层测试（97 个）

| 文件 | 数量 | 覆盖 |
|---|---|---|
| `test/core.test.js` | 49 | 成长、衰减、冷却、打工结算、**疾病三链四期**、对症下药、死亡复活、**学习九科**、**旅行纪念品**、商店、存档 v1→v4 迁移 |
| `test/host.test.js` | 17 | 路由注册与方法校验、快照形状、**拒绝操作必须诚实报 ok:false**、打工/生病/死亡走完整路由、命令 fallback |
| `test/client.test.js` | 31 | 在**伪造 DOM 里真跑 `client.js`**：挂载、动画标记、六图标、逐标签页内容、按钮置灰、点击 POST、告警横幅、toast、**旧版载荷不出现 undefined**、无 body 不崩、敌意 DOM 不崩、卸载 |

客户端测试是重点：它 `await import('../client.js')`，用一个假的
`window.__ModuleLoader__` 截住自注册，再用假 DOM 执行真实的 `apply()`。
**"不会动 / 按钮没反应 / 商店空着" 这类问题都能在这里复现。**

### 运行时验证

每次安装后**探真实服务**，而不是看日志文件在不在：

```
GET  /dsh-pig/state   → 200，且返回体里有 hatched / coins / health / jobs / shop
POST /dsh-pig/act     → 200，且 ok 字段反映操作真实结果
```

对照一个不存在的路由（404）来确认路由匹配确实起作用。

> 反面教材：早期我用 `~/.dsh/dsh-web.log` 判断服务状态，但用户手动前台启动时
> 输出打到终端、不写那个文件，日志是**陈旧内容**（token 和重启前一样）。
> 教训：**判断服务状态要看服务自身的行为证据**（路由响应、状态接口），
> 不看日志文件是否存在、也不看进程启动时间。

## 没做到的 / 已知不足

诚实记录：

1. **`desktop-companion` 那次事故** —— 我装之前扫了它用哪些 `ctx.*`、确认了
   `connection.rpc` 存在，但**没检查它声明的 inject 列表够不够覆盖实际触达的服务**。
   结果它调用 `rpc.handle()` 时内部读 `ctx.webServer`，因为没声明而抛异常。
   教训：**"服务存在" ≠ "它有权访问"**。后续所有插件筛选都改成检查真实调用链。
2. **修完没复检** —— whale-girl 的补丁我改完就交付了，没有在重启后主动验证
   （是用户重启后我自己去查的路由）。bug #10 也是同类：交付后没回看。
3. **UI 只靠伪造 DOM 验证** —— 动画"好不好看"、布局"舒不舒服"没法自动断言，
   只能靠用户看。测试能保证不崩、能渲染、能点，但保证不了好看。
4. **原版 `Menu/ditu*.png` 没解析出内容** —— 下载后发现是 9×33 的小碎片
   （图标栏两端 + 箭头），不是完整面板底图。原版的完整视觉参考只能靠截图。
5. **`study` / `trip` 没做原版的等级门槛** —— 原版有前置条件，
   本插件只校验金币和饱食，为了保持轻量。这是个有意的简化，不是遗漏。

## 关于 #13 和 #14：关于"我到底看没看"

三个 UI bug（#11 收起态重叠、#13 猪飞出屏幕、#14 验证工具失效）有一个共同点：
**它们全都在我"测试全绿"的情况下存在。**

| | 我断言的 | 真实情况 |
|---|---|---|
| #11 | `bar.hidden === true` ✅ | 浏览器照画不误（`display:grid` 压掉了 `hidden`） |
| #13 | 元素存在、数据正确 ✅ | 400px 窗口下猪在 `top: -24` |
| #14 | `pigMoved === 0` ✅ | 两次测的是同一个状态，函数根本没生效 |

所以现在的规矩：

1. **UI 改动必须在真实浏览器里看一眼**，不能只看断言。`tools/preview.html` 就是为此存在的 —
   `xdg-open dsh-pig/tools/preview.html`，有 `pigStub.setOpen()` / `pigStub.tab()` / `pigStub.state()`。
2. **量位置时要关掉动画**。`getBoundingClientRect()` 返回的是**变换后**的包围盒，
   `dp-bob` 的 `rotate(-2.5deg)` 会让它凭空变大 2px —— 我第一次量到的"移动 8px"
   全是动画噪声。
3. **验证工具本身也要被怀疑**。#14 是其中最阴的一条：工具坏了，却给出了一个
   "通过"的结果。看到 `moved: 0` 时我该先问一句"它真的切换了吗"，
   所以现在 `setOpen()` 返回实际状态，测量脚本把它一并打出来。
