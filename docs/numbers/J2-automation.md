# J2 自动化数值单（第二轮实施基准）

> 2026-10-09 用户拍板：所有新帮工仓最多装六小时工作产出，各级都须 4～6 小时满；满级每小时至多 400 金币等值；旧 30/60 分钟自动钓原样保留。用户随后明确选择保留实物菜，允许调整帮工作物周期和自动收成。
> 本轮不升存档版本，扩展仍为 2.1.0（未发版）。首轮固定格仓、慢熟菜 720 小时、600 时薪、v13 迁移全部撤回。

## 1. 仓统一按时间封顶

选择「当前速度 × 六小时」的时间口径。三种新仓都记累计工作毫秒 usedMs，上限 21600000；物品数只是这段工作已完成的实际收成，不作为固定容量。六小时封仓，任何等级 / 作物都一样。矿车 / 谷仓原升级改成效率工具，不增加格子。

- 矿工：累计产矿时间，按当前镐和矿车速度产实物矿，最多累计六小时。满后不积欠账，收一下倒进矿石袋并把仓的计时归零。
- 菜园：轮流处理所管理的地，实物菜进谷仓。每种作物用独立的小批次自动周期；同作物每六小时恰好安排整数批，所以哈密瓜也会六小时封仓并有实物收成。混种最后未完成的小批次保留在地块进度中，收仓不复制这份进度。
- 新长时钓鱼：累计 120 / 240 分钟行程的工作时间；六小时仓期包括失败竿和行程内空竿，不按成功鱼数量硬塞格子。短行程既不占这个仓，也不消耗它的时间。每趟到点仍回来，不自动续趟。
- 缺种子 / 缺鱼饵会停；恢复从当前动作时点继续，不追补停工收益。时间回拨不会重新给物品。满仓后只保留至多六小时的产出，不设每日上限。
- 净时薪扣每批种子或每竿鱼饵；不摊销一次性工具费。扩展汇率均为 1，测试折成金币。随机矿 / 鱼是期望时薪，不能保证每个自然小时的随机开奖都不超过 400。

实际预算还取「同作物、同管地数手动净时薪的 70%」和 400 的较小值。六小时按整数批取整，部分作物 / 档位的升级可能达到上限或落在同一批次数内，实际时薪以表为准。

自动单批收成不超过原作物收成：先取在起步六小时预算内能完成的一批实物（向日葵 2 个，西瓜 / 葡萄 / 哈密瓜 1 个，其余沿用原收成），每批消耗 1 颗对应种子；收的仍是原作物，售价、食用用途不改。批次数 = floor(六小时预算 / 单批净利润)，单批周期 = 六小时 / 批次数。帮工逐块处理，而非让每块地都按手动生长时间独立循环。

帮工自动周期不改变手动作物成熟时间（哈密瓜手动仍 12 小时），不改手动售价 / 收成；肥料不提高帮工预算。帮工免费浇水，不消耗猪饱食；缺种子停在空地，收一下倒进原作物仓库。

## 4. 自动钓鱼：旧短行程原样，新长行程单独计算

### 原有 30 / 60 分钟

从 origin/main 保留原出发和结算逻辑：每 3 分钟一竿，10 / 20 个鱼饵出发时预付，鱼直接进原背包；不受新仓满、抄网、鱼饵盒的影响。未购买长时升级的老玩家体验不变；新 400 限额不反过来改旧短行程。

### 新增 120 / 240 分钟

- 时长解锁：两小时 2000，四小时 5000，按顺序买；每 4.5 分钟一竿，一趟最多 26 / 53 次。
- 鱼篓恒定六小时工作产出；原鱼篓格数升级改成抄网效率：普通抄网附送（×0.8），顺手抄网 1500（×0.9），轻巧抄网 4000（×1）。
- 长时自动成功率 = 原自动成功率 ×0.7 ×抄网效率；鱼价、鱼竿、手动成功率不改。只降低新长时收益。
- 小鱼饵盒 1500，每趟最多自动补 16 个；大盒 4000，64 个。没有盒的新长行程仍预付本趟所需饵；有盒从背包逐竿扣，不足也可出发，用完停止。未用的预付饵退回。
- 旧行程仍入背包；只有新长行程入新鱼篓，收一下再入背包。ensureFishing 补 automation 默认字段，不升 STATE_VERSION，不裁旧鱼，不重复结算重启前的进度。
