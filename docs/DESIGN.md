# 设计说明

> 这份文档回答两个问题：**为什么是现在这个样子**，以及**每个数值从哪来**。
> 改动历史见 [CHANGELOG](../CHANGELOG.md)，开发过程见 [PROCESS](archive/PROCESS.md)。

---

## 1. 目标

在 DSH 里养一只 🐖。它应该：

1. **吃真实工作长大** —— 你干活它就长，不干活它就饿、会脏、会病
2. **完全不用敲命令** —— 所有操作都能点出来
3. **零成本** —— 不花 token、不注册模型工具、模型不知道它存在
4. **能活很久** —— 关掉 DSH 期间照样在推进，重开时一次性结清

第 4 条决定了整个架构：**没有任何定时器，一切基于时间戳惰性结算**。

## 3. 数值映射

原版用几千的绝对值，本插件用 0-100 的横条（好画、好读），阈值按比例换算：

| 属性 | QQ 宠物 | dsh-pig | 换算 |
|---|---|---|---|
| 饥饿 | 上限 3100，<720 报警 | 饱食 0-100，<**25** 报警 | 720/3100 ≈ 23% |
| 清洁 | 上限 3100，<1080 报警 | 清洁 0-100，<**35** 报警 | 1080/3100 ≈ 35% |
| 心情 | 上限 1000，<100 报警 | 心情 0-100，<**35** 报警 | 放宽了一点，对写代码的人客气些 |
| 健康 | **5**（0 = 死亡） | **5**，原样保留 | 不变 |
| 喂食 / 洗澡 / 逗玩 | +1000 / +1000 / +100 | +22 / +50 / +16 | 按比例 |

**未采纳**：`上限随等级涨`（`3000 + 100 × min(level, 30)`）。0-100 的横条如果上限也浮动，
比例条的语义就乱了；本插件用固定上限 + 等级只影响成长阶梯。

## 4. 架构

### 4.1 模块职责

```
data.js     静态游戏表，只有数据没有行为
             疾病链 · 9 门课 · 3 学段 · 4 个目的地 · 工作 · 商店 · 阈值
core.js     纯状态机，无 IO、无 ctx、无自带时钟
             每个函数都接收 nowMs 参数 → 整个游戏模型可单测、不用等
store.js    持久化：原子写 + 节流；把 core 的纯函数接到磁盘
render.js   所有文案与 ASCII 立绘（命令、HTTP、测试共用一份声音）
index.js    宿主半边：事件接线 + /pig 命令 + state/act 两个路由
client.js   客户端半边：手写 __ModuleLoader__ 脚本 + DOM + 动画 + 面板
```

### 4.2 三个关键决定

**① 时间戳惰性结算，不用定时器**

`decay(state, nowMs)` 是唯一让时间流逝的地方。它一次做四件事：

1. 结算已到点的外出活动（打工 / 上课 / 旅行）
2. 衰减饱食 / 心情 / 清洁（外出时 ×1.8）
3. 累积生病风险（饱食 <25 或 清洁 <30 时）
4. 推进未治疗的疾病（每 25 分钟一期）

好处：关掉 DSH 三天再打开，猪照样饿了三天、班照样打完了、病照样加重了 ——
一次性结清并弹出公告。**没有任何 setInterval 需要恢复。**

**② 外出统一成 `activity`**

打工、学习、旅行本质是同一件事：*猪离开一段时间，回来时结算*。
所以只有一个字段：

```js
activity = { kind:'work'|'study'|'trip', key, stage?, label, emoji,
             startedAt, endsAt, cost }
```

"猪在不在家"只有一个判断来源（`awayBlockedReason`），`decay()` 也只有一个结账点
（`finishActivity`）。三个平行字段会立刻带来"两个同时为真怎么办"的问题。

**③ 客户端不做任何假设**

`client.js` 的第一道工序是 `normalize(raw)`：把宿主发来的**任何**载荷
（当前的、旧版的、被截断的）映射成面板需要的确定形状。

```js
var num = (v, dflt) => (typeof v === 'number' && isFinite(v) ? v : dflt)
var str = (v, dflt) => (typeof v === 'string' && v !== '' ? v : dflt)
var arr = v => (Array.isArray(v) ? v : [])
```

这是被真实事故逼出来的：宿主还没重启、客户端已经刷新 → 新客户端读旧字段 →
满屏 `undefined`、商店空白。现在同样的错配会退化成合理默认值 + 一条
"宿主是旧版本，重启 dsh 之后才会出现"的说明。

### 4.3 数据流

```
       被动事件                     主动操作
  agent/turn-stopping          POST /dsh-pig/act
  agent/inbox/claimed   ┐      {action:'feed'|...}
  agent/error           ├──┐          │
  tools/result          ┘  │          ▼
                           ▼     OPERATIONS 表
                    store.feed()      │
                           │          │
                           ▼          ▼
                     core.feed()   core.act()/startWork()/startStudy()/startTrip()
                           │          │         buy()/useItem()
                           └────┬─────┘          │
                                ▼                ▼
                          decay(state, now) ← 唯一的时间入口
                                │
                                ▼
                     state（原子写 → $DSH_HOME/dsh-pig/state.json）
                                │
                                ▼
                          snapshot(store)
                                │
                    ┌───────────┴───────────┐
                    ▼                       ▼
            GET /dsh-pig/state      /pig 命令的输出
                    │
                    ▼
            client.js normalize() → 六个图标的面板
```

```
│         🐖           └───────┘ │
├──────────────────────────────┤
│ 📋  📚  💼  🛒  🧳  🎒        │  ← 奶油色图标栏（照原版截图 2）
│ 状态 学习 打工 商店 旅行 背包  │
├──────────────────────────────┤
│ 🍚 饱食 ▓▓▓▓▓▓░░░░ 62%        │  ← 内容区（随图标切换）
│ ❤️ 心情 ▓▓▓▓▓▓▓░░░ 74%        │     属性条**带标签**（照原版「宠物档案」）
│ 🫧 清洁 ▓▓▓░░░░░░░ 41%        │

```

**没有背景**：原版有蓝天草地，但那是给企鹅的舞台布景。🐖 直接站在卡片上更干净，
也不用为了渐变去迁就配色。云和草的元素已删除。

### 5.2 交互

| 动作 | 结果 |
|---|---|
| 点猪 | 折叠 ↔ 展开 |
| 拖动 | 移动位置（记在 localStorage） |
| 点图标 | 切换内容区，图标高亮 |
| 点猪（展开状态下） | 摸摸（专属动画 + ❤️） |
| 悬停 | 猪抬一下头 |

### 5.3 动画

常态呼吸摇摆（6px + 2.5° 倾斜，1.8 秒）。**心情驱动**：开心加速到 1.15 秒、
困了改慢速鼓气、饿了左右抖、脏了蒙蜡黄、病了咳嗽、死了静止变灰。

**每个动作有专属动画和粒子**：喂食跳起 + 🍎、洗澡摇摆 + 🫧、玩耍 360° 旋转 + 🎾、
摸摸被按下又弹起 + ❤️、出门 + 💼📚🧳、升级连蹦 + ✨🎉⭐。

四种粒子（`work` / `study` / `trip` / `cure`）与四种外出/治疗结果对应，
公告以 toast 形式从顶部滑入。

### 5.4 视觉语言：动森风格

配色与形态来自 [guokaigdg/animal-island-ui](https://github.com/guokaigdg/animal-island-ui)
的 `docs/design-system`。那个项目把设计规范单独成套（token、设计法则、逐组件像素级规格），
其中 `css-variables.md` 是**专门为"不装这个库也复刻这套风格"准备的 `:root` 模板** ——
本插件是纯 DOM、不用 React，正好吃这一份。

**token 声明在组件根节点而不是 `:root`**：宿主页面的自定义属性既不该被污染，
也不该能反过来覆盖这里。

| 角色 | 取值 | 用途 |
|---|---|---|
| 主色 | `#19c8b9` 薄荷青 | 主按钮、焦点环、链接 |
| 文字 | `#794f27` / `#725d42` / `#9f927d` / `#8a7b66` | 标题 / 正文 / 次要 / 弱化 |
| 背景 | `#f8f8f0` 主 · `rgb(247,243,223)` 内容区 · `#fffbe7` 输入 | 奶油羊皮纸 |
| 边框 | `#e5dcc6` 浅 · `#c4b89e` 常规 · `#a89878` 悬停 | 一律 2px |
| 选中 / 悬停 | `#b7c6e5` / `#d6dff0` | 图标栏与分段控件 |
| 3D 底边 | `#bdaea0`（通用） / 主色加深（青按钮） | 游戏按压感 |
| 状态 | `#6fba2c` 成功 · `#f5c31c` 警告 · `#e05a5a` 错误 | |
| 圆角 | 12 / 20 / 50px | 小件 / 卡片 / 药丸 |
| 缓动 | `cubic-bezier(.4,0,.2,1)`，0.15–0.35s | 全局 |

照规范的硬规则执行的几条，**都是会明显影响观感的**：

- **卡片用边框表达层次，不用投影**（规范第 8 条）。这里唯一例外是浮层本身 ——
  它需要一个暖色 `rgba(61,52,40,.16)` 的柔光把自己从页面背景里抬起来，
  而规范明确允许这个色调，只是要求"永不冷黑"。
- **厚 3D 底边只给主按钮**（规范第 5 条）。所以照顾按钮是奶油药丸 + 柔和浮起，
  只有 `买` / `出发` / `使用` 这类真正"执行"的按钮才是青色 + `0 3px 0`。
  规范原话说的是：给所有按钮都加 3D 底边会让界面"太重、太游戏化"。
- **禁止纯黑文字、冷灰背景、蓝色焦点环**（规范第 1/2/4 条）。属性条的四种颜色
  直接取自它的 island app-tile 调色板。
- **字体字重不低于 400**（第 12 条）：正文 500、按钮与标题 700。
- **图标栏就是它的侧边栏**：规范里侧边栏选中态是 `#b7c6e5`，这里六个图标横向摆放，
  选中态用的是同一组 token。

字体按规范的"独立复刻"配方从 Google Fonts 加载 `Nunito` + `Noto Sans SC`
（`display=swap`，非阻塞）。token 里的字体栈带完整系统回退，
**加载失败或离线时只是没那么圆，不会坏掉**。

## 6. 边界与已知限制

- **HTTP 路由不走主应用鉴权围栏**（DSH 既有行为，whale-girl 等插件同样如此）。
  服务只绑 `127.0.0.1`，但本机其他进程能读到状态、也能触发操作。
  状态响应刻意**不含任务标题**。
- **公告队列上限 6 条**，超出丢最旧的。
- **纪念品轮换是确定性的**（按 `stats.trips % 3`），不是随机 —— 为了让测试可断言，
  也保证每种纪念品都能收集到。
- **不做 `study`/`trip` 的等级门槛**：原版有前置条件，本插件只校验金币和饱食，
  保持轻量。
