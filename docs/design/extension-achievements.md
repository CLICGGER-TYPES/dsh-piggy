## 扩展作者使用的接口

动作通过 `api.emit(name, payload)` 报告已经完成的事实；`api.eventVersion === 1`。宿主把来源绑定到正在执行的扩展 key，调用方不能替别的扩展报告，也不能直接操作主存档或解锁徽章。

这是成就用的进度事件接口，不是执行任意代码的消息总线。事件目录及字段放在 `packages/pet-core/src/data/extension-events.js`；新扩展增加目录与成就数据，无须改动作执行器。

| 来源 | 事件名 | 必需字段 | 含义 |
|---|---|---|---|
| farm | harvest | total, items | 本次安装以来收获块数；已收获作物 key |
| mine | ore | total | 本次安装以来挖出的矿石数 |
| mine | fossil | items | 已发现的化石 key |
| mine | depth | maximum | 本次安装以来抵达的最深层数 |
| gacha | spin | total | 本次安装以来成功领取的颗数 |
| gacha | machine | items | 成功领取过的机器 key |
| gacha | gold | total | 本次安装以来获得的金色奖励次数 |
| blindbox | figure | items | 得到过的摆件 key |
| blindbox | six-star | items | 得到过的六星摆件 key |

`total` 是非负安全整数的累计量，不能传增量：收获第二块就上报 2，而非再上报 1。`maximum` 同样是非负安全整数。`items` 是最多 128 个标识的数组，key 遵守 `[a-z0-9][a-z0-9-]{0,39}`；可上报全集或新增项，宿主取并集。目录外事件、额外字段、负数、NaN、小数、过长数组等返回 false，均不写入记录。一笔动作最多接收 24 次报告。

示例（只在成功收获并更新自己的累计记录后执行）：

```js
if (typeof api.emit === 'function') {
  api.emit('harvest', { total: completedHarvests, items: acquiredCropKeys })
}
```

扩展模块声明 `eventVersion: 1` 表明支持此协议；`progress` 历史钩子仍可省略，仅实时报告的扩展也不会被误判成旧版本。

旧宿主没有 emit，四个扩展会跳过报告，玩法仍可运行。客户端没有公共 emit HTTP 路由；事件由扩展的宿主代码报告，不接收客户端直接指定成就进度。

## 历史补录

扩展可以提供可选的纯钩子 `progress(data) => [{ name, ...payload }]`。宿主在加载/更新扩展时传入它私有数据的克隆，校验整批报告、提交进度并静默解锁。钩子不能修改主状态，也不能获取金币/背包 API；抛错或无效报告整批回滚，通过已有日志记录原因，不影响其它扩展。

- 菜园使用 acquired 记录和每种固定产量推算已完成块数，不使用当前仓库，卖掉的收获仍算。
- 矿洞旧数据只能证明当前矿石袋、已发现化石/宝石、当前层数；已出售且没有计数的旧矿石、此前更深但已重置的层数无法还原。新数据增加 oreCount/deepest，往后保留。
- 扭蛋旧记录只有最近 30 颗和最后一次机器；只据此补录最低可证明的数量、金色奖励和最后机器，不把动作 seq 当作颗数，不猜另外两台。新数据增加 milestones，完整保留之后的经历。
- 盲盒用有效 owned 记录补录摆件及六星，旧 1.0 数据先由扩展自己的 normalize 转换；没有记录的收藏不猜测。

补录徽章的 firstAt 为 null、recovered 为 true，显示完成日期未知。新达成记录宿主 checkpoint 的时间；一次获得多枚仍合并提示。不会伪造历史时间。

## 幂等、事务与存档

新增可选 `achievements.events[source][name] = { total, seen, items, maximum }`，仍为存档 v12。共享核心只消费公共报告，既不导入扩展 server.js，也不读取 extData 内部字段。

- 累计报告只增加 `max(0, reported - seen)`，seen 不随旧报告下降；相同或乱序旧报告不重复计数。
- 集合取并集、最高值取最大值，无无限增长的事件 ID 列表。
- 扩展动作在私有事务副本上执行；金币、背包、说话、私有数据和事件在成功后一次提交。返回 ok:false 或抛错全不提交。接口维持同步动作约定。
- view 只获得读取副本，emit 永远返回 false；刷图鉴、反复读快照、重启或更新均不产生新报告。
- 更新保留 seen；真正重新安装或新一代重新开始扩展时，重置计数基线，保留跨代 total、收藏、最高层及徽章。扩展作者不得在同一次安装里自行清零累计字段；需要从头开始时应走卸载/重装。
- 完整重置清空；禁用不推进；卸载删除扩展私有数据，却保留主存档中的成就经历。
- 这是受信任扩展的事实报告，并不提供反作弊或代码沙箱；调试/手改存档及不诚实扩展可能伪造自己的经历。

## 发布衔接

主游戏包更新和下载扩展更新是两件事。本分支保留游戏/外壳版本，不推发行标签，也不发布 npm；维护者选定下个游戏版本后发布即可。

四个扩展源码及 manifest 已准备好：farm/mine/gacha 1.1.0、blindbox 2.2.0。minGame 仍为 0.31.0，因为 emit 是可选能力，旧宿主运行玩法不报错；新成就须同时使用带事件接口的新游戏和新版扩展。

不能把现有在线目录指向尚未存在的发行附件。本 PR 不修改 registry.json/registry-gitee.json；发布顺序：

1. 合并并发布新游戏包。
2. 为四个扩展分别创建 ext-farm-1.1.0、ext-mine-1.1.0、ext-gacha-1.1.0、ext-blindbox-2.2.0 发行附件，内容为各目录的 manifest.json/server.js/client.js；Gitee 同步镜像。
3. 运行 `node scripts/extension-entry.mjs <key>` 与带 `--host gitee` 的命令，按实际附件生成 hash 和 URL，再更新两个在线目录（详见 extension-download.md）。
4. 玩家在扩展中心更新对应扩展，数据保留并静默补录成就；尚未更新时有明确提示。

测试用本地假目录提供真实四扩展包，不依赖网络，也不写玩家存档。不能据此声称公开发行附件已经上传。
