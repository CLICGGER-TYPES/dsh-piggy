# 扩展的自动化路线（K1：交给 codex 做，Claude 验收）

> 用户 2026-10-09：「这几个扩展游戏你都最好以增量游戏的想法去设计，这样比较好玩耐玩一点」；随后「让 codex 去做，然后后面你来验证验收」。
> 第一～三节是设计，第四节是给实现者的任务清单，第五节是验收标准。数字都是初稿：实现者先出数值单 J2 给用户确认，**确认前不写玩法代码**。

## 一、几条规矩（跟经济设计一致）

1. **先手动，后自动**：每个扩展一开始都要自己点；自动化要在商店里用扩展币买，一级一级升（跟一键种满一样，增量游戏的路子）。
2. **自动的比手动的慢**：自动化的时薪落在**挂机线**（起步 60～120，满级 800～1200），永远低于自己玩的主动线（300～2500）。自己玩永远更划算，挂着也有进账。
3. **攒满就停，不设每天上限**：自动产出先进一个「仓」，仓满了就不再产，要回来收一下。仓的大小决定「多久回来看一眼」——这就是轻度上头的钩子，又不限制想一直玩的人。
4. **离线也算**：按真实时间结算（跟打工一样），关了游戏回来一次性结清，最多结到仓满。
5. **不碰抽卡**：盲盒、扭蛋不做自动化（自动抽卡等于自动花钱）。
6. **画风**：动森式的「请个帮手」——都是一只小猪帮工 + 一件道具，不做数字面板和进度条墙；界面上只多一行「帮工在干活 · 仓里 23/40 · 收一下」。

## 二、每个扩展

### 矿洞：⛏ 小矿工猪
- 买了以后，小矿工猪在你选的电梯站往下挖，挖到的矿进「矿车」。
- 升级三条线：**镐**（跟你自己的镐共用，越好挖得越快）、**矿车**（仓：容量 30 → 60 → 120 → 240 块矿）、**头灯**（能去更深的电梯站）。
- 初稿：雇佣 3000 矿石币；满级约 600 矿石币/小时，矿车满级装 4～6 小时。

### 菜园：🧑‍🌾 帮工猪
- 已有的洒水器管浇水。帮工猪再管**熟了就收、收了就补种**（用你仓库里的种子，没种子就停）。
- 升级：**管几块地**（2 → 4 → 8）、**谷仓**（仓：收的菜放这，满了就不收）。
- 初稿：雇佣 2500 菜币；满级约 600 菜币/小时（扣掉种子成本），谷仓满级装 4～6 小时。

### 钓鱼：🎣 自动钓鱼加长
- 现在已经有「让猪自己去钓 30 / 60 分钟」。增量路线是把它升级，而不是另做一个帮工：
  - **鱼篓**：自动钓回来的鱼放鱼篓，加大容量；
  - **时长**：解锁 2 小时、4 小时的自动钓鱼；
  - **鱼饵盒**：自动钓鱼按设好的鱼饵自己补（从背包扣）。
- 初稿：三样各 1500～5000 金币，满级约 600 金币/小时（扣鱼饵）。

### 盲盒、扭蛋
- 不做（见规矩 5）。

## 三、三个待定点（用户未单独回答，先按建议执行；用户有异议以用户为准）

1. **三个都做**：矿洞小矿工猪、菜园帮工猪、钓鱼加长自动钓。
2. **帮工和猪打工可以同时进行**：帮工是扩展里的东西，跟猪出不出门无关；但帮工满级时薪压在 ≤ 600/小时（挂机线下半段），这样打工 + 帮工合起来也不离谱。
3. **仓满 4～6 小时**：早上、中午、晚上各回来看一眼。

## 四、实现清单（给实现者）

先读：[AGENTS.md](../../AGENTS.md)、[经济设计](economy.md)（规则 1 钱包、规则 2 不设每天上限、规则 3 收入区间）、[写扩展](../guides/writing-extensions.md)、[J1 数值单](../numbers/J1-economy.md)（现在的菜园、矿洞、钓鱼数字都在这）。

### 第 0 步：数值单 J2（先交用户确认）
- 新建 `docs/numbers/J2-automation.md`：每样帮工 / 升级的名字、价格、每级产出、仓容量、满仓要多久。
- 在 `tools/economy-sim.mjs` 里加帮工的时薪算法，把每一级的时薪写进 J2，落在第一节规矩 2、第三节第 2 条的区间里。
- J2 交给用户确认，确认后才做第 1～3 步。

### 第 1 步：矿洞（`extensions/mine/`，2.0.0 → 2.1.0）
- 帮工的状态存在扩展自己的 data 里：雇了没有、各升级几级、`lastAt`（上次结算时间）、矿车里有什么。
- **结算靠时间差**：每次动作开头和 `view()` 里按 `api.now - lastAt` 算这段时间挖了多少，最多到矿车装满（`view()` 只算不写；动作里才写回 data）。不需要改宿主。
- 新动作：`hire`（雇）、`upgrade`（升级某条线）、`collect`（把矿车里的矿倒进背包 / 直接卖成矿石币，二选一按 J2）。都用矿石币（`api.wallet`）。
- 帮工挖到的矿不触发连挖加成、不给宝箱和化石（这些留给自己玩），不累猪（不调 `api.exert`）。
- 界面：矿洞页顶上一行「⛏ 小矿工猪在第 6 层 · 矿车 23/60 · [收一下]」；没雇时这一行是「雇一只小矿工猪 3000 ⛏️」。升级放进矿洞的商店货架（`shelf`）。

### 第 2 步：菜园（`extensions/farm/`，2.0.0 → 2.1.0）
- 帮工猪管几块地（按级数）：这些地熟了就收、收完用仓库的种子补种同一种作物；没种子就停在空地上，界面写「没有××种子了」。
- 收的菜进「谷仓」，谷仓满了就不收（作物留在地里熟着）。`collect` 把谷仓倒进现有的仓库。
- 跟洒水器叠加：有洒水器的地全自动；没洒水器的地帮工也浇水（J2 定要不要算进升级）。
- 结算方式同矿洞：按时间差补算，最多到谷仓满。注意 `advancePlot` 已经能按时间推进作物，复用它。

### 第 3 步：钓鱼（宿主，`packages/pet-core/src/core/fishing.js`）
- 自动钓鱼现在只有 30 / 60 分钟（`startAutoFishing` 里写死 `[30, 60]`，`migrate.js` 认 `auto-30` / `auto-60`，界面 `src/client/tabs/fishing.js` 写死两个按钮）。
- 加三样，用金币在钓鱼页买（跟鱼竿一样一级一级买）：**时长**（解锁 120、240 分钟）、**鱼篓**（自动钓回来的鱼先放鱼篓，有容量）、**鱼饵盒**（按设好的鱼饵从背包自动扣，不够就少钓几竿而不是不能出发）。
- 存档字段加在 `state.fishing` 里，`ensureFishing` 补默认值；老存档不用升 STATE_VERSION 就能读（加字段有默认值即可；真要升版本按 CONVENTIONS 走）。

### 每一步都要
- `npm run build && npm test && npm run typecheck` 全绿；文件 ≤ 400 行（`test/conventions.test.js` 守着）。
- 新测试：结算按时间差、仓满就停、离线很久回来只结到仓满、钱不够买不了、老存档（没有帮工字段）能读、经济区间（用模拟函数，参照 `test/fishing-gear.test.js` 最后一个测试）。
- 扩展改了就升版本、`minGame` 写对，两份目录 `extensions/registry.json` 和 `registry-gitee.json` 用 `node scripts/extension-entry.mjs <key> [--host gitee]` 重算那一条。
- 新 emoji 要重新裁网页版字体：`uv run --with fonttools --with brotli python tools/slim-emoji-font.py --web-out assets/piggy-emoji.woff2`（`test/emoji-coverage.test.js` 会提醒）。

## 五、验收标准（Claude 验收时逐条对）

1. J2 数值单用户确认过，代码里的数字跟 J2 一致。
2. 模拟：每一级帮工时薪在区间里，满级 ≤ 600/小时；自己玩永远比帮工赚得多（同一扩展、同一工具档对比）。
3. 时间：关掉游戏 1 小时 / 1 天回来，结算的量对（1 小时按速度算，1 天只到仓满）；把电脑时间往回拨不会倒扣、也不会白给。
4. 删扩展：帮工、仓里的东西跟着扩展走，钱包按汇率结清，宿主不留脏数据。
5. 界面在 Linux 虚拟机和 Win11 虚拟机里看过：没雇 / 雇了在干活 / 仓满 / 没种子 四种状态都对，面板没被撑宽（[界面规范](../guides/ui-style.md)：简洁，不加说明废话和刻度条）。
6. 测试、类型检查全绿；版本号、目录校验值、CHANGELOG、文档都对。
