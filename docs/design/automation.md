> 用户 2026-10-09：「这几个扩展游戏你都最好以增量游戏的想法去设计，这样比较好玩耐玩一点」；随后「让 codex 去做，然后后面你来验证验收」。

> 第二轮修正（2026-10-09）：用户拍板仓按六小时工作时间封顶、满级净时薪 ≤400；保留实物菜并允许调整帮工周期 / 自动收成。旧 30/60 分钟自动钓完全沿用原逻辑。当前基准见 [J2](../numbers/J2-automation.md)。构建、818 项测试、类型检查和双平台复测通过；截图放在仓库外，PR #10 待再次验收。

## 一、几条规矩（跟经济设计一致）

1. **先手动，后自动**：每个扩展一开始都要自己点；自动化要在商店里用扩展币买，一级一级升（跟一键种满一样，增量游戏的路子）。
2. **自动的比手动的慢**：自动化的时薪落在**挂机线下半段**（起步推荐配置 60～120，满级 ≤400），低于自己玩的主动线（300～2500）。具体作物 / 鱼饵例外及计算口径按用户授权采用 J2；不能用平均时薪掩盖某个时段超标。
3. **攒满就停，不设每天上限**：自动产出先进一个「仓」，仓满了就不再产，要回来收一下。统一六小时仓期决定「多久回来看一眼」——这就是轻度上头的钩子，又不限制想一直玩的人。
4. **离线也算**：按真实时间结算（跟打工一样），关了游戏回来一次性结清，最多结到仓满。
5. **不碰抽卡**：盲盒、扭蛋不做自动化（自动抽卡等于自动花钱）。
6. **画风**：动森式的「请个帮手」——都是一只小猪帮工 + 一件道具，不做数字面板和进度条墙；界面上只多一行「帮工在干活 · 仓里 1.0/6时 · 收一下」。

## 二、每个扩展

### 矿洞：⛏ 小矿工猪
- 买了以后，小矿工猪在你选的电梯站往下挖，挖到的矿进「矿车」。
- 升级三条线：**镐**（跟你自己的镐共用，越好挖得越快）、**矿车**（仓：六小时工作产出；矿车升级加速，不增加格数）、**头灯**（能去更深的电梯站）。
- 初稿：雇佣 3000 矿石币；满级不超过 400 矿石币/小时，矿车各级六小时封仓。

### 菜园：🧑‍🌾 帮工猪
- 已有的洒水器管浇水。帮工猪再管**熟了就收、收了就补种**（用你仓库里的种子，没种子就停）。
- 升级：**管几块地**（2 → 4 → 8）、**农具效率**（谷仓收实物菜，六小时工作封仓）。
- 初稿：雇佣 2500 菜币；满级不超过 400 菜币/小时（扣掉种子成本），谷仓各级六小时封仓。

### 钓鱼：🎣 自动钓鱼加长
- 现在已经有「让猪自己去钓 30 / 60 分钟」。增量路线是把它升级，而不是另做一个帮工：
  - **新鱼篓**：只存 120/240 分钟的鱼，恒定六小时工作产出；升级抄网提高收鱼效率；
  - **时长**：解锁 2 小时、4 小时的自动钓鱼；
  - **鱼饵盒**：自动钓鱼按设好的鱼饵自己补（从背包扣）。
- 初稿：三样各 1500～5000 金币，满级不超过 400 金币/小时（扣鱼饵）。

### 盲盒、扭蛋
- 不做（见规矩 5）。

## 三、三个待定点（用户未单独回答，先按建议执行；用户有异议以用户为准）

1. **三个都做**：矿洞小矿工猪、菜园帮工猪、钓鱼加长自动钓。
2. **帮工和猪打工可以同时进行**：帮工是扩展里的东西，跟猪出不出门无关；但帮工满级时薪压在 ≤ 400/小时（挂机线下半段），这样打工 + 帮工合起来也不离谱。
3. **各级仓最多六小时**：第二轮统一改为累计六小时有效工作封仓，各级都适用；缺种子 / 鱼饵停工不补发，不再保留慢熟菜例外。

## 四、实现清单（给实现者）

先读：[AGENTS.md](../../AGENTS.md)、[经济设计](economy.md)（规则 1 钱包、规则 2 不设每天上限、规则 3 收入区间）、[写扩展](../guides/writing-extensions.md)、[J1 数值单](../numbers/J1-economy.md)（现在的菜园、矿洞、钓鱼数字都在这）。

### 第 0 步：数值单 J2（先交用户确认）
- 新建 `docs/numbers/J2-automation.md`：每样帮工 / 升级的名字、价格、每级产出、仓容量、满仓要多久。
- 在 `tools/economy-sim.mjs` 里加帮工的时薪算法，把每一级的时薪写进 J2，落在第一节规矩 2、第三节第 2 条的区间里。
- J2 交给用户确认，确认后才做第 1～3 步。
- 当前基准由 `tools/economy-sim.mjs` 核算：矿工最大 386.53、菜园最大 400.00、新长时自动钓最大 361.96；用户已授权按 J2 实施价格、矿石比例、帮工收获周期和钓鱼间隔。

### 第 1 步：矿洞（`extensions/mine/`，2.0.0 → 2.1.0）
- 帮工的状态存在扩展自己的 data 里：雇了没有、各升级几级、`lastAt`（上次结算时间）、矿车里有什么。
- **结算靠时间差**：每次动作开头和 `view()` 里按 `api.now - lastAt` 算这段时间挖了多少，最多到矿车装满（`view()` 只算不写；动作里才写回 data）。不需要改宿主。
- 新动作：`hire`（雇）、`upgrade`（升级某条线）、`collect`（把矿车里的矿倒进背包 / 直接卖成矿石币，二选一按 J2）。都用矿石币（`api.wallet`）。
- 帮工挖到的矿不触发连挖加成、不给宝箱和化石（这些留给自己玩），不累猪（不调 `api.exert`）。
- 界面：矿洞页顶上一行「⛏ 小矿工猪在第 6 层 · 矿车 1.0/6时 · [收一下]」；没雇时这一行是「雇一只小矿工猪 3000 ⛏️」。升级放进矿洞的商店货架（`shelf`）。

### 第 2 步：菜园（`extensions/farm/`，2.0.0 → 2.1.0）
- 帮工猪管几块地（按级数）：这些地熟了就收、收完用仓库的种子补种同一种作物；没种子就停在空地上，界面写「没有××种子了」。
- 收的菜进「谷仓」，谷仓满了就不收（作物留在地里熟着）。`collect` 把谷仓倒进现有的仓库。
- 跟洒水器叠加：有洒水器的地全自动；没洒水器的地帮工也浇水（J2 定要不要算进升级）。
- 结算方式同矿洞：按时间差补算，最多到谷仓满。帮工按 J2 小批次周期处理实物作物；手动地块继续用 `advancePlot`，不改成熟时间与手动收成。

### 第 3 步：钓鱼（宿主，`packages/pet-core/src/core/fishing.js`）
- 自动钓鱼原来只有 30 / 60 分钟（`startAutoFishing` 里写死 `[30, 60]`，`migrate.js` 认 `auto-30` / `auto-60`，界面 `src/client/tabs/fishing.js` 写死两个按钮）。
- 加三样，用金币在钓鱼页买（跟鱼竿一样一级一级买）：**时长**（解锁 120、240 分钟）、**鱼篓**（自动钓回来的鱼先放鱼篓，有容量）、**鱼饵盒**（按设好的鱼饵从背包自动扣，不够就少钓几竿而不是不能出发）。
- 按用户本轮要求不升存档版本；`ensureFishing` 补 `automation` 默认值。旧 30/60 分钟每 3 分钟一竿、预付饵、直接进背包；新 120/240 分钟才用新鱼篓、鱼饵盒及 4.5 分钟间隔。新行程进度在重启时保留。

## 五、验收标准（Claude 验收时逐条对）

1. J2 数值单用户确认过，代码里的数字跟 J2 一致。
2. 模拟：每一级帮工时薪在区间里，满级 ≤ 400/小时；自己玩永远比帮工赚得多（同一扩展、同一工具档对比）。
3. 时间：关掉游戏 1 小时 / 1 天回来，结算的量对（1 小时按速度算，1 天只到仓满）；把电脑时间往回拨不会倒扣、也不会白给。
4. 删扩展：帮工、仓里的东西跟着扩展走，钱包按汇率结清，宿主不留脏数据。
5. 界面在 Linux 虚拟机和 Win11 虚拟机里看过（codex 自测一遍、Claude 验收再看一遍）：没雇 / 雇了在干活 / 仓满 / 没种子 四种状态都对，面板没被撑宽（[界面规范](../guides/ui-style.md)：简洁，不加说明废话和刻度条）。
6. 测试、类型检查全绿；版本号、目录校验值、CHANGELOG、文档都对。
