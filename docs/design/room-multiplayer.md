# 联机房间（多猪同屏）设计

状态：2026-11-05 第一版实现。桌面版专属；不改存档结构。

## 目标

同一局域网里，多位玩家各自带自己的猪进同一个房间，在同一扇窗口里看到所有猪，
可以走一走、摸摸、挥手。人数不写死，主机容量上限 32（只在服务端兜底，界面不显示“最多几只”）。

原型图（`work/20261105-piggy-multiplayer/output/prototypes/`）只作视觉参考；
实际窗口按桌面版现有形态做：一扇普通的带标题栏窗口，可缩放、可最小化，不做无边框透明窗口。

## 非目标（第一版）

- 不共享存档、金币、背包、状态；别人的猪只是“外观 + 位置 + 表情”。
- 不做公网、账号、好友列表、长期设备身份、跨进程回执。
- 不做房间内小游戏、喂食、交易。
- 不做断线自动重连（房间还在时可以重新输入房间码加入）。

## 为什么不是现有 owner LAN

现有「局域网联机」把一台设备的 OwnerDocument 猪开放给另一台设备，加入方看到的是
**同一只猪**的只读会话。房间需要每个人带自己的猪，因此另做一层纯中继：

- 主机进程里跑一个内存房间服务，只保存玩家列表、外观摘要、位置和表情；
- 每个客户端仍然只读写自己的存档；
- 主机离开房间就关房，所有人的房间窗口收到「房主已关闭房间」。

## 房间协议

HTTP/1.1，绑定具体私有 IPv4，随机端口。请求体上限 4 KiB，只接受 `application/json`。

| 路由 | 认证 | 内容 |
|---|---|---|
| `POST /v1/room/join` | 房间码 | `{ clientId, code, profile }` → token、自己的 playerId、玩家列表、版本号 |
| `POST /v1/room/state` | Bearer | `{ since }`，长轮询最多 15 秒；版本变化立即返回 |
| `POST /v1/room/update` | Bearer | `{ rev, x, y, facing, emote, targetId }`；x/y 都是 0..1，y 控制前后排，节流 30ms |
| `POST /v1/room/leave` | Bearer | 离开房间 |

- token 32 字节随机数，服务端只存 SHA-256；不写磁盘。
- 每个玩家 30 秒没有任何请求就移除；长轮询本身算心跳。
- 版本号在玩家加入/离开、位置或表情变化时递增；通知以 40ms 合并，避免一次移动打一串响应。
- `profile` 只接受名称、等级、阶段、立绘路径和显示尺寸；立绘路径限定在
  `/dsh-piggy/art/pigs/…` 或本机导入皮肤 `custom-…`，对端没有这张图时退回默认小猪。
- 表情：`wave`（挥手）、`pat`（摸摸，可指定 targetId）、`jump`（跳一下）。
  服务端记录 `emoteAt`，对端只演 1.8 秒内的新表情。

## 房间码与发现

- 房间码 4 位，字符集去掉容易看错的 `0 O 1 I`；显示为 `PIG-7K2M`。
- 主机在 UDP 47823 上监听发现请求：`PIGGYROOM/1 <code>` → 回复 `PIGGYROOM/1 <httpPort>`。
- 加入方向各网卡的广播地址和 `255.255.255.255` 发探测，1.2 秒内取第一个回复。
- 防火墙挡住广播时，输入框也接受完整邀请串 `piggy://<私有 IPv4>:<端口>#PIG-XXXX`。
- 一台机器同一时间只能开一个房间（UDP 47823 独占）；错误信息直接说明。

## 窗口与入口

- 主屏新增「联机」App 方块（桌面版才显示）。面板里是原型第一、二张那种大厅/房间卡片。
- 创建或加入成功后，主进程打开一扇 `piggy://room/room.html` 的房间窗口（role=room），
  默认 760×500、最小 520×360、居中、可缩放，奶油底。
- 房间窗口里：顶部状态和房间码、草地上所有猪、名字/等级/房主标记、
  底部「摸摸 / 挥手 / 离开房间」；自己的猪可以在 2.5D 地面拖动，或用方向键 / WASD 按住连续移动（上下控制前后排，可斜着按）；Shift 加速 1.35 倍；走路时立绘像纸片人一样左右轻晃，阴影保持贴地。活动范围按场景地面轮廓圈出，小屋、家具、池塘、树等作为碰撞体阻挡，撞到边界会停下，可斜着按绕开。场景前景（猪圈树、房间书架/书桌/沙发）按物体底边深度和猪一起排序，猪走到后面会被前景挡住。猪立绘的脚底对齐脚下阴影，碰撞只取阴影中心一个点，不按整只猪或阴影面积算。
- 窗口关闭等同于离开房间；面板里的联机页仍可再次创建/加入。
- 房间窗口是独立页面，不加载游戏包；只通过 `window.piggyShell.room` 与主进程通信。

## IPC

面板：`status / host / join / open / leave / copy`。
房间窗口：`state / move / emote / leave / copy`。
主进程推送：`piggy:room:update`、`piggy:room:closed`。

所有处理函数都校验发送窗口：只有面板能建房/加入，只有房间窗口能移动/发表情。

## 安全边界

- 只允许具体私有 IPv4 监听；不接受 `0.0.0.0` 作为地址参数（发现用的 UDP 除外）。
- 每个来源每分钟最多 20 次加入尝试；房间码比较用定时安全比较。
- 响应不回传 token 以外的服务端内部字段；错误只给可读原因。
- 不记录 token、房间码或玩家 IP 到日志。

## 测试

- 单元：房间码生成/归一化、profile/位置校验、广播地址计算。
- 集成：本机起服务 + 两个客户端加入、长轮询收到变化、移动/表情、离开、房主关房。
- 客户端：联机页在大厅/房间两种状态下的渲染与按钮。
- 手动：两台机器同一 Wi-Fi 创建/加入；一台机器开两个实例做形状验证。

## 地图边界编辑器（2026-11-06）

房间窗口右上角「边界」进入编辑模式，顶部是可复用工具栏：地图菜单（猪圈/房间、恢复默认）、对象类型按钮（边界节点/矩形障碍/圆形障碍/手绘障碍）、新建/编辑/删除三个通用模式按钮、撤销、快捷键、完成。对象类型只决定新建什么；新建/编辑/删除对每种对象复用，不再给每种对象各做一套按钮。当前提示显示在底部状态条。外边界用「边界节点 + 新建」点地面加节点，新点会插入最近的一条边、不会接在末尾拉出尖角；已有节点在新建/编辑模式下都能直接拖，删除模式点节点删除。障碍支持矩形、圆形和手绘任意斜边多边形；矩形和圆形都从左上往右下拖出包围盒，圆形按包围盒内切圆生成。编辑模式点击障碍会显示选框和节点：拖四角白点等比例缩放，拖粉色节点改形状（矩形/圆形会转成多边形），拖障碍内部移动。手绘障碍是画笔式：点地面加节点，按住 Shift 吸附 45° 直线，点第一个点/最后一个点或双击闭合。快捷键：V 编辑、N 新建、E 删除、1–4 切换对象类型、Delete 删除选中、Ctrl/⌘+Z 撤销、Ctrl/⌘+Shift+Z 重做、Esc 取消、Enter 闭合手绘；工具栏 ? 打开完整列表。撤销按钮常驻工具栏，没有可撤销步骤时置灰；恢复默认在地图菜单里。数据按场景存 `localStorage: dsh-piggy:room-walk-areas`，改完立即用于碰撞和淡边界显示。

右侧对象面板暂时移除，后续再定侧边展示什么；障碍结构编辑和删除都在画布上完成。
