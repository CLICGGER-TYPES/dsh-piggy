# 外部桌宠合并规则

本文是 0.37.2-rc.5 公开实现的说明，不是新规则。字段清单、默认值和事务语义都以当前公开源码为准；提交代码时，规则表是 `packages/pet-core/src/core/merge-rules.js` 的 `MERGE_RULES`，实际合并入口是 `packages/pet-core/src/core/merge.js` 的 `mergeSaveStates`。

本文不逐项断言所有字段都相加或取最大。下表只列会影响用户理解的关键字段；没有登记规则的源端字段不会被静默合并：预览会要求用户选择丢弃或中止，目标端已有但规则表没有的字段则原样保留。

## 适用范围

- 只适用于用户明确发起的「把内嵌猪合并到桌面猪」，不是默认行为，也不会自动后台合并。
- 两边存档都必须能加载并迁移到当前 v15（旧版本会先迁移，不要求原本就是 v15）；任一边存档版本高于当前实现，或内嵌端合并规则版本高于桌面端，拒绝合并。
- 至少有一只是活着且已孵化的小猪。具体可合并组合由界面按两边状态给出，例如两只都活着，或只有一边活着而另一边已离开；两只都未拆盒、都离开或状态读不出来时不合并。
- 两边不能有进行中的打工、上课、旅行、番茄钟、手动钓鱼或自动钓鱼。未到点的活动可以按用户确认强制终结，退款、鱼饵、次数按当时实际状态结算。
- 疑似同一份存档的副本不硬拦截，但提交前必须显式选择保留哪一边，或明确选择仍然合并。

## 资产与收集

| 数据 | 合并规则 |
|---|---|
| 金币 `coins` | 两边相加，封顶 `Number.MAX_SAFE_INTEGER`。 |
| 物品 `inventory` | 按物品 key 逐项相加，逐项封顶。 |
| 扩展币钱包 `wallets` | 同一 key 余额相加；名称、汇率、可购买性等元数据跟桌面猪，两边不同时给警告。 |
| 总账 `economy` | 各来源收入/支出相加；按天并集，同一天逐来源相加，保留最近 7 天；疲劳取较大。 |
| 图鉴 `dex` | key 并集；同一项计数相加、首次时间取较早、鱼的最大尺寸取较大。 |
| 已解锁成就 `achievements.unlocked` | key 并集，首次时间取较早。 |
| 成就统计 `achievements.totals` | 取「两边相加」和「合并后统计」中的较大值。 |
| 成就事件 `achievements.events` | 计数相加，条目并集并按上限截断。 |
| 装扮 `dress` | 并集。 |
| 纪念品 `souvenirs` | key、获得时间、名称都相同才去重；同 key 不同时间保留多件。 |
| 自定义皮肤 | 同 key 且图片哈希相同则去重；同 key 内容不同时把内嵌皮肤改名（如 `-2`）共存；最多 128 套。 |
| 鱼篓/自动钓鱼库存 | 按 id 并集；id 冲突时给内嵌鱼换新 id，两条都保留；最多 512 条。 |
| 工作收据 | `(source, id)` 并集，只保留 7 天窗口内；两边同一 `(source, id)` 只有 `type` 或 `at` 不同时保留桌面猪并警告，其他字段不同不触发警告；合并后超过 20,000 条时拒绝合并，不截断。 |

## 进度与状态

| 数据 | 合并规则 |
|---|---|
| 经验 `xp` | 取较大值；等级由合并后的经验重新计算。 |
| 年龄 `ageMs` | 取较大值；出生时间、强制年龄标记跟年龄较大的一边。 |
| 体重 `weightG` | 跟经验较大的一边。 |
| 孵化/离开 | `hatched` 为两边逻辑或；`dead` 为两边逻辑与。 |
| 资料修改次数 `profileEdits` | 取较大值。 |
| 属性、课程、兴趣 | 按 key 逐项取较大值。 |
| 统计 `stats` | 按 key 逐项相加。 |
| 饱食、心情、清洁 | 只有一边活着时用活着的一边；两边都活着时取较高值。 |
| 健康与疾病 | 健康按同样规则取生命方或较高值，再受疾病阶段上限约束；疾病取更早的阶段。 |
| 进行中状态 | 活动、番茄钟、钓鱼待处理状态必须为空；合并后的活动清空。 |

## 身份与偏好

身份分四组，每组可以跟桌面猪、跟内嵌猪，或在桌面端给出候选时自己改：

| 组 | 字段 | 规则 |
|---|---|---|
| 名字 | `name` | 选边时原样保留，不截断旧长名字；自己改时上限 5 字。 |
| 样子 | `form`、`skin`、`worn` | 形态必须在合并后已解锁；界面候选只列 `default`、合并后已解锁的内置皮肤和合并后的自定义皮肤。提交校验接受 `default`、所有内置皮肤 key（不要求已解锁）和合并后的自定义皮肤；穿戴必须在合并后已拥有的装扮里。 |
| 性格 | `personality`、`catchphrase`、`motto`、`birthday` | 性格必须是可用项；自己改时口头禅 1-6 字、签名 1-24 字，生日必须是合法月/日。 |
| 偏好 | `ownerName`、`quiet`、`isOfflineFeedEnabled`、`timeScale`、`fishing.spot` | 称呼 1-12 字；时间倍率大于 0 且不超过 365；钓点必须在合并后已解锁。 |

默认值：名字、样子、性格跟「基础身份方」——两只都活着时跟桌面猪，只有一边活着时跟活着的一边；偏好默认跟活着的桌面猪，桌面猪不活着时跟内嵌猪。选择「自己改」不会消耗普通资料修改次数。

## 扩展

- 只有桌面端已经安装、并且声明了合并钩子的扩展才调用钩子。
- 钩子正常返回且没有未解决冲突时，采用钩子给出的数据。
- 钩子抛错、返回非法数据或报告未解决冲突时，降级为逐个二选一，默认跟桌面猪，不会把半成品写进存档。
- 两边都有数据但没有钩子的扩展，逐个二选一，默认跟桌面猪。
- 只有内嵌猪有数据的扩展会复制到桌面猪；如果桌面端没有安装该扩展，数据保留并提示需要重新安装后才能使用。
- 扩展数据不会由游戏本体直接加载；安装和运行仍由扩展自己的协议负责。

## 疑似同一份存档

满足任一条件时提示疑似副本：

- 两边 `seed` 相同，且出生时间相差不到 5 秒。
- 名字、经验、金币中至少两项相同，或徽章重合度达到 80%。

预览只提示，不自动决定。提交时必须选择：

- 只保留桌面猪：不做任何相加，内嵌猪只留在合并前备份里。
- 只保留内嵌猪：不做任何相加，桌面猪只留在合并前备份里。
- 仍然合并：按普通字段规则处理，预览会警告资产可能被重复相加。

前两项的结果是选中一边结算后的状态，不会把另一边的金币、物品或徽章加进来。

## 事务与恢复

### 预览

- 预览只读取桌面状态并计算，不写目标存档。
- DSH 侧冻结源端、生成预览归档，并在预览成功后生成一份源端完整备份；备份写入后重新解压校验。
- 预览有效期 10 分钟。同一时间只保留一个预览；新预览替换旧预览。
- 取消、过期或桌面拒绝时，DSH 恢复源端暂存状态；如果发起前是「只连接」的暂存模式，则恢复到该模式，不擅自切回内嵌猪。

### 提交

1. DSH 提交时带 `mergeId`、预览令牌、选择、源备份名和源归档 SHA-256。
2. 桌面端重新校验预览仍在、令牌正确、未过期、源归档哈希一致；预览后桌面运行时重载或状态有变化时拒绝，要求重新预览。
3. 桌面端弹出原生确认框；60 秒内没有确认按拒绝处理，默认按钮是取消。DSH 的提交请求最多等待 90 秒。
4. 确认后先生成目标存档完整备份并重新解压校验。备份失败不写合并结果，也不删旧备份。
5. 写入使用独立事务目录和日志：只处理 `state.json`、工作收据和本次涉及的皮肤文件；失败时按日志恢复替换前的文件。目标/源端备份、`backups/merge-history.json` 合并历史和 `backups/merge-<mergeId>/` 事务记录由事务流程另外写入，不在这个写入日志的覆盖范围内。不会整目录替换，不会删掉扩展目录、日志或窗口设置。
6. 写入成功后重载运行时；重载失败时尝试用刚写的备份恢复，并明确返回失败原因。

### 结果未知

- DSH 没收到明确结果时，把状态记为 `merge-unknown`，只用同一个 `mergeId` 查询桌面端状态，不重新提交。
- 桌面端按 `mergeId` 返回已提交结果；同一 `mergeId` 的重试返回同一结果，不会重复应用。
- 查询到 `committed` 时继续退役。
- 查询到 `failed` 或 `rolled-back` 时立即恢复源端。
- 查询到 `unknown` 时保持 `merge-unknown`，源端继续待恢复；持续用同一 `mergeId` 查询，不重新提交。
- 查询结果变为 `committed`、`failed` 或 `rolled-back` 时，立即按该状态处理。
- `unknown` 持续超过 2 分钟，恢复源端暂存并保留现场。

### 退役

- 合并成功后，内嵌猪先写退役标记和配置，再停内嵌运行时，最后分别幂等改名 `state` 和 `work-events`。
- 启动时只认原路径；看到退役标记就不打开 `merged-*`，只补齐没完成的改名步骤。
- 退役某一步失败时，桌面合并结果保留，DSH 标记为待重试；用户可以重试退役，不会重新合并。

### 撤销与备份

- 只能撤销最近一次合并；更早的合并记录只保留血缘信息，不能直接撤销。
- 桌面端撤销时，先用合并前备份恢复目标，再把「合并后的桌面进度」另存为一份备份；只删除本次合并复制且哈希未变的皮肤文件。
- DSH 侧再恢复源端备份和内嵌猪；若桌面端已恢复而 DSH 恢复失败，返回「部分撤销」，保留可继续恢复的状态。
- 只恢复内嵌猪是独立路径，不撤销桌面端。
- 合并备份只保留最近一次可撤销所需的一套。清理只碰合并记录里登记的合并备份和 `merge-<id>/` 目录；普通手动导出/导入备份永远不碰。
- 合并记录损坏或读不出时，不清理任何旧备份，等人工处理。
