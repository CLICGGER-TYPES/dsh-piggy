## 范围与来源

保持现有养成、1008 句台词、12 种性格、奖励和冷却规则；保留 DSH、桌面猪/面板/扩展窗口使用同一游戏包的方式。新视觉和玩法先出可审稿件；已授权的 bug 修复按证据推进。

学习依据：Coopanion `04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33` 的 [窗口](https://github.com/Pal-AI-Lab/Coopanion/blob/04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33/packages/cortico-world-desktop-pet/host/electron-main.cjs)、[对话与布局](https://github.com/Pal-AI-Lab/Coopanion/blob/04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33/packages/cortico-world-desktop-pet/web/pet-app.js)、[鼠标续约](https://github.com/Pal-AI-Lab/Coopanion/blob/04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33/packages/cortico-world-desktop-pet/host/mouse-lease.cjs)、[角色布局报告](https://github.com/Pal-AI-Lab/Coopanion/blob/04ce022a8c1e96e6053d9cbbe8f6dc555aa93f33/packages/cortico-world-desktop-pet/web/body-host.js)。只学习责任划分、状态和几何约束，代码、图形、动作全部独立实现；不拷贝该仓库实现到本项目。

源码核查发现：参考项目把宠物/菜单/气泡放进覆盖一块工作区的透明舞台，测量气泡后约束屏边并调整尾巴；对话和动作分别有队列，状态提示让位于对话；角色报告头顶锚点、命中区、身体状态；主进程对点击捕获设有效期。其跨屏实现也专门处理新视口确认和松手交接，不能因此认为整屏窗口自动解决所有问题。本轮没有运行参考项目，不声称其全部平台表现已经验证。

## 气泡职责

目前入口涉及 `pending.js`、`io.js`、`effects.js`、`split.js`，绘制边界由 `desktop/measure.js` 与外壳原生形状共同决定。先用完整真实路径复现长礼包裁切；DOM 宽高正确不代表桌面绘制正确。

新的气泡控制器收口的是当前消息、回复 ID、显示计时与关闭/取消；不同时承担养成或窗口创建。第一步保留现有领取合并和 2600/4000/至少 6000ms 的已发布行为，先做行为等价替换。展示来源应显式区分台词、待回复、奖励回执与状态提示。以下新策略是设计候选，须审后采用：普通闲聊等待未回复问题；相同状态更新原状态；紧急消息的打断与恢复；需要多长时间自动关闭。不能把所有 pending 排队后播出已失效回复，也不能反复清空正文重置滚动。

事件 ID 去重、当前有效 reply ID 与养成发奖仍在既有层处理。面板和猪窗口共收快照时，只有猪窗口演角色消息；DSH 单实例本地演。关闭/切换存档/卸载统一取消计时器和回调。

本轮已修一个具体交互边界：回复按钮在自动关闭前按下、关闭后松手，原实现会隐藏按钮并丢掉 click。`effects.js` 复用 `createRenderHold` 保护回复行到本次点击完成，消息代号使旧计时器、排队隐藏和旧 click 失效；取消/失焦释放、卸载清理。普通显示时长和消息替换规则不变。原生复验中跨到期松手只有一次合法回复、没有摸摸；后续收口控制器时必须保留这一合同，不能以新队列再次绕开。

## 几何合同

内部计算使用明确的逻辑像素坐标。区分四种空间：立绘归一化坐标、页面布局坐标、桌面 DIP、绘制物理像素；跨空间转换有唯一入口，不能把 screenX、DPR、scaleFactor 混用。

角色提供脚底中心、头顶气泡锚点、小手接触点、原始可见范围和可点范围；动画额外提供本阶段绘制包络。静止布局不从呼吸变换后的矩形反推，不改现有五帧/抛掷节奏。先从现有 `art-framing.js`、`motion-envelope.js`、`feel/envelope.js` 组合，经过验证再消除重复推导。

气泡布局读取实际宽高、有效视口和头顶锚点，返回正文框、尾巴位置、绘制范围、交互范围。DSH 的有效视口来自宿主页面，桌面来自当前工作区与原生窗口；两端输入不同，共用布局约束。消息显隐不改变猪的屏幕脚底位置。长正文和回复保留原滚动能力，画面边缘必须被原生窗口真正容纳，不能只修 CSS 的 z-index。

本轮真实点击还发现头顶区域内部的空间冲突：签到成功后约 180ms，下一颗礼物按钮已出现，但回执气泡盖住同一中心；`elementFromPoint` 命中正文，未发出礼包请求，也未误触摸摸。这与原生窗口裁切、错误触摸路由是不同问题。后续布局稿必须同时安排正文、回复与奖励控件，不能只夹气泡后留下不可点击的按钮，也不能用隐形按钮穿透正文或简单抬高层级来假装修好。屏顶长文本的垂直空间不足也需一起设计；在具体稿确认前，不擅自把消息挪到猪下方或更改控件显隐规则。

小手接触点按当前形态、皮肤与朝向映射。自动估计只是自定义包初始值；帽子、巨大透明边和非标准头型需要校准，不承诺仅凭包围盒准确定位头部。

本轮原生裁切复现进一步确认：方形 `pig` 定位盒不能同时充当完整绘制边界。旧正式版在整数 DPR 1/2 下，边缘拖放会把 `commitSlide` 转成持久 anchor；82px 定位盒位于 384px 原生窗口的 x=302 时，宽立绘仍越过右边。回到屏幕内侧也不会自动消除这个局部越界。单纯事后清 anchor 的候选曾在原生录像中产生约 103 个物理像素的单帧跳动，已撤回。

修复采用独立、从原布局重算的 `visual` 包络，组合宽立绘与现有动作极限，变换中心仍取原猪定位盒。拖动、抛掷和启动位置必须使用同一边界；全局可见还须验证转换后的局部范围确实落在原生窗口内。`pig`、home、面板锚点及 `commitSlide` 保持原义。新外壳通过可选 `dragVisualBounds` 能力标记声明拖动支持；新包在旧壳可运行，但不能宣称旧壳获得这项边缘拖动修复。已存在的坏 anchor 通过保留同存档重启恢复，不做有跳帧的运行中清零。

## 手势与窗口职责

交互目标先在可见控件和角色之间分流。按钮/回复等控件独占其按下到松手链路；角色的按下、抚摸、拖动、抛掷、落地按明确状态转换，保持既有阈值、速度与养成冷却。拖动捕获和窗口有效期是一项平台能力，不应在每个按钮里修一次。

统一诊断记录目标类别、动作、消息 ID、坐标空间、当前显示器/缩放、请求与原生边界；不记录玩家台词正文或凭据作为常驻日志。高频记录有节流，诊断能关闭。已有拖动心跳与鼠标命中去重先核对再复用，不另叠一套轮询。

跨屏从源坐标重算目的坐标，几何交接一次并有确认，松手与交接顺序须有回归。保留现有抛掷可穿相连屏缝的行为，不直接照搬参考项目跨屏松手清速度或临时隐藏身体的策略。

## 整屏透明舞台实验

仅在独立 VM 配置和隔离分支/临时入口进行，发布主线保持原实现。对比现有小猪窗口+独立面板与工作区透明舞台：两者用同一存档副本、文本、路线和画面条件；记录窗口绘制完整性、菜单/回复点击、桌面空白和任务栏透传、主副屏与负坐标、显示器拔插恢复、输入焦点、失联释放，以及至少一分钟相同待机/动作条件的 CPU、GPU、内存。

以当前实现测得的数字作为性能基线再设验收阈值，不先编绝对性能数字。减少常驻绘制，静止不引入高频动画循环；适用平台不足或资源退化就保留原架构。该实验不作为裁切 bug 修复的前提，不为实验提前提高 minShell。

## 验收

每次先旧版同路线失败，再修后同路线通过；原生桌面录屏、实际鼠标与同屏几何数据必须一致。组合包含菜单开/关、短/长/带回复消息、普通/胖瘦/帽子/自定义、屏中/左右边缘、拖前/落地后；先定向覆盖变更相关部分，再做综合验收。

强制 Electron DPR 只证明强制 DPR 条件，不能代称操作系统缩放、混合 DPI 或另一平台。Linux、Windows、macOS 实测与未覆盖项分开列。DSH 另验宿主滚动、面板开关、回复和扩展隔离；旧档迁移、旧外壳能力探测、build/typecheck/相关测试作为逻辑门槛，不代替画面验收。
