## 页面与奖励

入口复用图鉴，不增加主菜单 App。分组陈列彩色/灰色小猪徽章，始终可见名称和目标，点击可看详情。颜色、绶带、书本、鱼、王冠等小配件区别主题；主体沿用原作小猪矢量轮廓和配色。

首版只有徽章，没有领取按钮、金币、属性和商店加成。一个 checkpoint 同时达成多个目标时，只产生一条合并提示；免打扰时遵循现有通知规则。

## 存档与结算

- 存档 v12，新增可选 `achievements: {unlocked, totals, seen}`，通过 `ensureAchievements` 清洗。`unlocked` 保存首次解锁时间和历史补录标志；`totals` 保存跨领养累计量；`seen` 保存上次已结算的当前猪统计。
- 主逻辑放在共享核心：对现有成功动作统计的正向增量累计，宿主在保存 checkpoint 调用。工作、课程、旅行必须完成后现有统计增加才解锁；拒绝、提前叫回、重复轮询不增加。
- 领养继承记录；新一代现有统计归零后重新建立基线，避免重复计数。完整重置清空成就。
- 老存档首次加载按现存统计、有效图鉴记录和当前形态静默补录。此前已经丢失的代际统计无法还原；未解锁成就也不会依据未知历史增加次数。
- 历史补录显示「完成日期未知」；新成就记录检测并解锁的时刻，离线归来时获得日期是本次结算时间，不冒充精确的历史发生时间。
- 展示函数只读；刷页面不会单独解锁或改变进度。旧客户端可以忽略新增快照字段，新客户端兼容旧快照。
- 不具备反作弊：调试修改统计、给予鱼和强制形态也可触发；是否区分调试记录是后续设计项。

## 试玩与验证

运行 `node tools/achievement-preview.mjs`，浏览器打开 `http://127.0.0.1:8780`。使用真实共享核心、隔离存档、HTTP 路由与构建后的客户端；顶部可切换示例进度、从零试玩、全部徽章。演示数据不是真实玩家经历。

自动测试覆盖首次解锁、重复轮询、拒绝照顾、完成工作/离线结算、存档重载、跨代累计、重置、历史补录、字段清洗、通知合并以及客户端详情返回。真实浏览器已查看图鉴入口与成就列表；贡献者已查看试玩页面和徽章。

本次完整回归测试 **656 / 656 通过**，`npm run build`、`npm run typecheck` 和 `git diff --check` 通过。`npm pack` 包含十六张徽章；解包产物成功运行喂食解锁、重复结算去重、领养继承及客户端新鲜度检查。

正式 DSH 插件和 Electron 安装环境未验收。Windows 基线的 emoji 字体测试存在 URL.pathname 导致 `C:\C:\...` 的路径错误，采用 `fileURLToPath` 修复，作为独立维护改动保留。
