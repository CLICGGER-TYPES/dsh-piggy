## New_play 规则分析

已读用户目录三图。明确规则：每颜色只放一只；周围八格不能再放；格子可排除标记。类似 Queens 逻辑谜题，而非填数字数独。LinkedIn 官方规则 https://www.linkedin.com/help/linkedin/answer/a6269510 同时要求每行、每列、每色各一枚，以及斜角不能相邻；图片未展示行列要求，不能直接当作已确认。

截图棋盘按行是 YGOO / YOOO / YSOO / YSSO。枚举每色一枚且不相邻，共 4 解；加入每行每列一枚后只剩 1 解：(1,2)、(2,4)、(3,1)、(4,3)。与两枚已展示的猫位置相符，支持行列规则被教程截图省略的推断。

若作为新扩展，建议用现有猪立绘作棋子：空格/排除/放猪、拖动批量排除、撤销/重开、冲突提示与有理由的提示。关卡须验证唯一解，难度按推理步而非纯格数控制。名称、完整规则、关卡量、奖励与收费均待用户审定，不动养成经济或复用其他扩展存档。

## React 评估

目前养成 core、存档宿主、共用客户端与 Electron 能力层已经分开，两端复用同一游戏包。React 可以帮助复杂面板组件与生命周期管理，但不能直接修 Electron 原生 shape、多窗口层级、跨屏坐标和 IPC 时序。大迁移会重新验证两端、老外壳兼容、扩展注册与动作动画，现阶段不建议全量重写。

优先明确快照/动作/平台桥边界，统一几何合同，减少轮询导致的整块 DOM 重建。后续若复杂面板确有维护收益，可选一个隔离扩展做 React 小范围试点，比较滚动/焦点保留、动画连续、内存和重绘结果再决定扩展范围；保留 core 与适配层，桌宠逐帧运动不交给 React 状态刷新。React 官方支持局部接入：https://react.dev/learn/add-react-to-an-existing-project 。
