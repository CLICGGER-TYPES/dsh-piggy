# 小猪显示大小：统一档位与立绘校准

状态：用户已选择统一一档并校准可见大小；实现已完成，桌面验收记录如下。

## 已确认的现状

- 设置里只有一份保存在当前设备的四档偏好：小、标准、大、特大。倍率分别为 0.85、1、1.3、1.7；它乘生命阶段的基础尺寸（幼年 54、青年 60、成年 68 像素），不改存档。
- 普通立绘、内置形态和导入皮肤都通过同一个 `--pig-size` 控制外框。换皮肤后会沿用当前生命阶段的尺寸；皮肤没有独立的大小偏好。
- 外框尺寸相同不代表看起来一样大。内置 SVG 皮肤的可见边界通常占 256×256 测量画布的约 90% 以上；反馈 PNG 的可见边界占约 60%–100%。猪递图占约 63%，默认幼年猪占约 93%，因此同选“标准”时猪递明显更小。
- 反馈图常带道具、场景；直接按透明边界自动裁剪或放大，会把道具一起放大，还可能改变已审定的构图。睡姿也单独使用 1.2 倍宽的图片盒，需要一并检查。

## 已确认的设置方式

**一份大小偏好适用于所有形态与皮肤。** 保留四档的交互，逐张校准立绘的可见尺寸，让同一档看起来接近。校准信息属于显示层，不改用户存档、生命阶段和原图。导入皮肤在加载后按透明像素测量一次；已知反馈 PNG 的测量结果由离线工具生成，避免切图时出现重新测量带来的尺寸跳动。

内置 SVG 形态和皮肤遵守同一 64×64 画布与对齐规格，继续按全局档位显示；不增加逐款皮肤设置。

## 实施与验收

1. 保持生命阶段尺寸、存档和养成规则不变；只改当前设备的显示偏好与画面尺寸。设置页说明一份档位覆盖普通猪、皮肤和睡姿。
2. 已知反馈 PNG 在构建前用 `tools/measure-feedback-framing.py` 测量透明边界，生成显示层校准数据。导入皮肤加载后在浏览器中测量一次并缓存。原图文件不变。
3. 桌面版的设置面板与猪分属两个窗口；监听本机存储变更后立即更新小猪窗口和桌面命中区域。Ubuntu 26.04 原生 Electron 外壳的普通猪“标准 → 特大”在点击后约 1 秒的截图中已放大；修前同样时间内仍是标准尺寸，约 4 秒后才更新。
4. Ubuntu 26.04 与 Windows 11 原生外壳均已目视检查普通猪、天使皮肤、饥饿反馈图；Windows 的“标准 → 特大”也在点击后约 1 秒的截图中完成放大。构建、类型检查和 748 项测试通过。截图存放在工作区 `dsh-piggy-artwork/pig-size-review/ubuntu/` 与 `dsh-piggy-artwork/pig-size-review/win11/`。导入皮肤的透明边界测量由针对性测试覆盖；睡姿沿用同一尺寸变量，尚未逐档实机截图。
