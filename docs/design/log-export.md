# 日志与导出（设置 → 日志）

给维护者看的：用户说「我这里不行」时，怎么在不看代码、不去那台机器的前提下知道发生了什么。

## 为什么要有它

在这之前，猪的现场是这样的：

- 网页版（DSH 插件）**没有任何可取的日志**。警告只走宿主进程的 stdout，用户看不到也拿不到；面板里抛的错、请求没送到宿主，宿主那边一片空白。
- 桌面版只有外壳自己的 `piggy.log`（窗口、更新、崩溃），**游戏那半边（存档、动作、扩展下载）写不进去**，因为它们在主进程里各写各的。
- 规则抛错被 `mutate()` 兜住后完全静默（现在会记一条并注明「改动已回滚」）。
- 扩展下载失败只留一句 `fetch failed`，连是哪个文件、连的哪台主机都不知道。

结果就是每次都要用户手工翻目录、截图、猜版本。

## 记什么

一条日志的形状：`时间 · 级别 · 范围 · 一句话 · key="value" 上下文`。

| 范围 | 记的内容 | 排障时能回答什么 |
|---|---|---|
| `boot` | 启动表头：游戏版本、渠道、存档版本、node / 系统 / 时区、运行形态、存档路径、DSH_HOME、外壳版本 | 这一版到底是什么？哪个渠道的包？ |
| `save` | 存档打开、版本迁移（含升级前留的副本路径）、读不出来 / 损坏留副本、写入失败 | 进度丢了吗？是老档迁移出问题了吗？ |
| `act` | 每个动作：耗时、成功还是被拒绝、拒绝原因（`reason`）、关键参数（item / key） | 用户到底点了什么？是没生效还是被规则拒绝？ |
| `ext` | 在线目录读取的每次尝试、每个扩展文件的下载尝试（地址、第几次、失败原因）、安装失败汇总 | 扩展为什么装不上？是网络还是校验？ |
| `core` | 规则抛错、改动整段回滚 | 界面上「没成」的背后是哪条规则炸了 |
| `client` | 浏览器里的未捕获错误、未处理的 Promise 拒绝、发不出去的动作、宿主断连与恢复 | 面板自己的问题（宿主日志永远看不到） |
| `shell` | 桌面外壳的窗口摆放、页面加载、渲染进程警告、更新、导出结果 | 桌面版「窗口不对 / 打不开」类问题 |
| `poll` | 只记「连不上宿主」和「恢复」两个转折点 | 断连发生过吗？什么时候？ |

不记的：平时的每一次轮询、每一次成功写盘（太吵，会把有用的部分挤出去）。级别分 `debug / info / warn / error`，导出时按时间排。

## 存在哪

- **内存**：始终留最近 800 条。网页版没有稳定可写目录，导出至少还能拿到这一份。
- **文件**：有存档目录时追加 `<存档目录>/logs/dsh-piggy.log`（一行一条 JSON）。满 1.5 MB 轮转成 `.1`，只留一份旧的。
- 网页版：`$DSH_HOME/dsh-piggy/logs/`；桌面版：Electron userData 下 `dsh-piggy/logs/`。

写日志永远不许影响猪：写不进去就停写并在启动头里留一句原因，不抛错、不阻塞。

## 导出怎么走

点「📄 导出日志」后：先把浏览器攒着的那批日志送给宿主（`POST /dsh-piggy/logs/client`，按 id 去重）→ 取回合成的一份纯文本（`GET /dsh-piggy/logs/export`，导出前先 flush 文件）→ 再选保存方式：

1. **桌面版**：`piggyShell.logs.save(name, text)` → 主进程 `dialog.showSaveDialog` → 写盘。真正的系统「另存为」。
2. **网页版**：`window.showSaveFilePicker()`。同样是系统对话框；用户取消时当没事发生。
3. **兜底**：`<a download>` + Blob。总得让用户拿得到。

老外壳（0.4.0 及以前）没有 `logs.save`，会自然落到第 2 / 3 条，功能不受影响。

## 验收

桌面版实测（2026-10-06，外壳 0.5.0）：

![设置里的日志入口](../screenshots/log-export-settings.png)

点「导出日志」后按钮变灰，主进程的 `dialog.showSaveDialog` 挂住等待用户选路径——功能与外壳那条路都通。

## 规矩

- 日志文案不用 emoji（代码规范），字段写成 `key="value"`，错误必须带上下文参数。
- 客户端送来的条目要过一遍清洗（形状、长度、级别白名单），脏数据不许进导出文件。
- 导出文件是给**人**读的：表头单独成行，正文一条一行，开头写清「共几条、有多少 error」。

## 相关的坑

- 新增的宿主侧模块要同时加进 `package.json` 的 `files` 和 `apps/desktop/scripts/pack-game.mjs` 的 `GAME_FILES`，否则 npm 包或桌面游戏包里会缺文件（`test/conventions.test.js` 守前一半）。
- 桌面外壳加了 `piggyShell.logs.save` 这种新基础动作，要升 `apps/desktop/package.json` 的版本和 `DESKTOP_VERSION`。
