# 日记展示与文案方案（2026-10-23，已确认并实现）

用户已确认“稍微发散一点，而不是流水账记录”，已完成正文改写与明细折叠。下方保留方向审阅时的示例，最终实现与验收见文末；任务状态只记 ROADMAP。

## 已查明的问题

当前日记有两条写入路径：离线照料把第三人称物品明细追加到 `entries[].text`；跨过06:00后，又把第一人称预写短日记追加到相同字段。面板把整段显示，所以同一天会混着“草莓×1、香皂×1”和“我……”的短文。用户10月22日的实际条目可复现这种混排。

现有日记本有15组、319条短文。按固定优先级选主事件，不是逐条记下所有操作；但照料小票和正文混排，会破坏语气，也让整段原文与预写句无法直接匹配，影响“最近没写过”的去重。部分旧文案还断言了计数不能证明的科目、职业、天气或主人说的话。

## 建议方向

- 每天仍写一篇，沿用06:00日界、现有选组顺序与触发阈值，不调整养成数值或奖励。
- 正文围绕一件真实主事件，用小猪第一人称写2到4句想法或感受，不把物品和次数排成清单。
- 照料结算放在同页可展开的“照料记录”，默认收起，明细不丢。
- 旧档原文不回写、不重写；`text` 保持完整兼容旧客户端。由快照派生正文和照料明细，新面板分别显示；旧宿主缺少派生字段时回退到原文。
- 只有照料小票、还未跨日生成正文时，不捏造一篇日记；具体空态提示随界面稿一起确认。
- 不新增持久化字段。将来若要记录更细的按日事实，必须先做存档迁移与跨日归属设计。
- 离线结算可能横跨多个游戏日，不能把归来时汇总的物品清单直接说成“今天吃的东西”。未能证明归属的细节不写入当日正文。
- 不凭空写主人说话、天气、具体职业、课程成绩、拥抱或身体症状；不默认“没人操作就是没人陪”，也不写持续睡了一整天。
- 不接游戏内云端生成或额外API消耗；先维护完整短文，避免机械拼句。
