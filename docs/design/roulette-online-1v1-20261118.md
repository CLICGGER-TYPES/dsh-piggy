# 左轮联机 1v1 设计定稿

日期：2026-11-18
状态：用户已拍板权威模型与首版范围，按本文件实施。
前置：`docs/design/roulette-rules-20261118.md`（单机 AI 规则已定稿并实现）、`docs/design/roulette-4p-online-proposal-20261118.md`（联机审计与 4 人提案）。

## 1. 用户拍板

| 项 | 决定 |
|---|---|
| 局域网 | 房主建房，房主客户端跑权威对局 |
| 公网 | 整套权威逻辑跑在公网服务器上，不依赖某个玩家的客户端 |
| 让枪费 | 双方让枪费都进底池，赢家通吃 |
| 金币 | 各扣各的：每个客户端按结算扣/收自己存档的真实金币 |
| 断线 | 不做重连；扩展大窗口关掉即结束对局，不后台占用 |
| 首版范围 | 与单机同规则：单局/三局两胜、1/3 命、装 1-5 发 |
| 观战/中途加入 | 不做；只在开局前加入 |
| 4 人桌 | 1v1 跑通后再做 |

## 2. 权威模型

### 2.1 局域网：房主客户端权威

- 房主扩展大窗口持有完整对局状态（含子弹位置），跑与公网权威相同的 JS 规则模块。
- 客人只发动作；房主把动作应用后广播脱敏快照。
- 房主关窗/退出房间，对局结束；客人按“房主离开”结算，不再等待。
- 房间服务器只做事件中继，不存牌局。

### 2.2 公网：服务器权威（方案 A）

- 公网服务器上跑一个无头 Node 权威进程（`apps/room-authority/`），直接复用 `src/extensions/roulette/online.js` 规则模块；规则只有一套。
- Rust 房间服务器新增游戏事件中继：玩家动作经 `/v1/room/game` 转给本机权威进程，权威返回事件后由房间服务器广播。
- 权威进程不接触任何玩家存档，也不验证金币余额；金币仍由各客户端本地结算。
- 权威进程与房间服务器通过 `127.0.0.1` + 共享密钥通信，不直接暴露公网。

## 3. 房间游戏通道

### 3.1 路由

`POST /v1/room/game`，Bearer 玩家 token（公网还接受权威进程的共享密钥头）。

请求体：

```json
{ "seq": 12, "ext": "roulette", "op": "action", "data": { } }
```

- `seq`：该玩家单调递增的动作序号；服务端按玩家记录最后 `seq`，旧包直接返回 `{ok:true, duplicate:true}`。
- `ext`：小写扩展键，1-32 字符；只允许 `[a-z0-9-]`。
- `op`：小写操作名，1-32 字符；只允许 `[a-z][a-z0-9-]*`。
- `data`：JSON 对象，序列化 ≤1536 字节，深度 ≤4，单字符串 ≤256 字节。
- 每个玩家限速 20 条/秒；事件队列保留最近 32 条。

响应：`{ ok, version, eventId }`。

### 3.2 事件

房间 `state` 响应新增 `gameEvents`：

```json
{ "id": 7, "from": "<playerId>", "ext": "roulette", "op": "snapshot", "data": { }, "at": 1763500000000 }
```

- `from` 由服务端从 token 推导，客户端不能伪造。
- `room` 视图新增 `caps` 与 `authority`：局域网 `{caps:["game"], authority:"host"}`；公网权威 `{caps:["game"], authority:"server"}`。
- 客户端按 `id` 去重，只增应用；首次进入先取一次完整 `state`。
- 对局期间双方每 5 秒发一条 `ping`（没有 `view`）。
  - 局域网（`authority:"host"`）：对手 20 秒没有任何事件视为离开——房主权威补发 `leave`，客人本地判底池归自己。
  - 公网（`authority:"server"`）：`ping` 由权威转成带 `from` 的事件，权威同时检查另一方是否已沉默 20 秒；掉线由权威替对手判认输，客户端不能按沉默自行结算，否则同一场会被两边各判一次赢。

### 3.3 两种服务端模式

- `host`：房间服务器只追加事件并广播。房主大窗口消费客人动作，发布快照。
- `server`：房间服务器把玩家动作 POST 给本机权威进程（`x-room-authority` 共享密钥），权威进程返回事件数组，房间服务器追加并广播。玩家事件不再直接广播给其他玩家，避免绕过权威。

### 3.4 权威进程接口（仅本机）

`POST /v1/game`，头 `x-room-authority: <secret>`：

```json
{ "room": "PIG-7K2M", "from": "<playerId>", "owner": true, "seq": 12, "ext": "roulette", "op": "action", "data": { } }
```

返回 `{ ok: true, events: [ { op, data } ] }` 或 `{ ok: false, reason }`。权威进程按房间维护对局；房间关闭/长时间无动作后回收。`owner` 由房间服务器按加入顺序判定，只有 `owner: true` 的玩家能 `create`；缺失或非 `true` 一律拒绝，房间服务器和权威进程必须一起升级。

## 4. 在线 1v1 规则

### 4.1 座位与开局

- 2 个座位：`host`（房主）与 `guest`（客人）。房主必须先在房间里；客人从房间进入左轮大厅点“加入牌桌”。
- 公网持久房间没有 `players[].host` 标记：按加入顺序的第一位玩家当房主（房间服务器按 joined_at 排序），第一位移出房间后自然轮到下一位；权威只接受 `owner` 的 `create`。
- `players[].host` 只是非持久房“房主离开即关房”的生命周期标记，不等于客户端权威；只有本机建房（`hosting`）或服务器权威（`authority:"server"`）才有开局权。
- 房主选设置：命数 1/3、单局/三局两胜、底注 100-10000、每局装弹数 1-5；客人加入时确认底注≤自己金币。
- 两人都就位后房主点“开始”；双方客户端各扣本场首局底注。后续每局开局再各扣一局底注。
- 每局装弹由房主操作（点弹孔或随机装弹）；装完服务端随机先手。客人在装弹阶段看到“房主装弹中”。

### 4.2 回合

- 当前座位只能二选一：对自己开枪，或让枪。
- 让枪费 = `ceil(底注 * 50%)`，由当前座位自己付，直接进底池；双方一致。
- 回让：A 让枪、B 让枪，枪回到 A，A 这一手必须开枪；服务端拒绝 A 继续让枪。
- 空枪换手；中弹扣 1 条命。
- 1 条命：中弹即输本局。3 条命：装 1 发中弹后重装，下一手给对手；装多发继续打当前弹巢，子弹打完再重装（与单机一致）。

### 4.3 结算

- 单局：本局结束即整场结束；三局两胜：先赢 2 局者结束，每局双方各付一份底注，底池跨局累积。
- 赢家拿底池。每个客户端按自己的账本计算：
  - 赢：`收入 = 底池`，净额 = `底池 - 累计底注 - 累计让枪费`。
  - 输：`收入 = 0`，净额 = `-累计底注 - 累计让枪费`。
- 双方让枪费都在底池里，所以赢家能拿回自己付过的让枪费，输家拿不回；不做“让枪费直接给对方”。
- 结算事件带 `matchId`、`handId`、`pot`、`paid`、`fees`、`winner`；客户端校验与本地记录一致后才入账，重复结算按 `matchId` 幂等丢弃。

### 4.4 离开与关窗

- 开局前主动点“离开牌桌”（第一局装弹中、还没开过枪）：本场取消，双方已扣的首局底注退回（沿用现有 `roulette-refund` 收入记账；宿主没有退款接口的限制不变）；直接关窗按下面的离开处理。
- 开局后离开/关窗：视为认输，底池归对手；离开方已付底注不退。客户端能上报就上报 `leave`；直接关进程时，局域网由房主客户端按 20 秒心跳沉默判负，公网由权威进程判负（见 3.2）。
- 房主关窗：本场按离开处理，底池归客人；房主已付底注不退，窗口关闭后不再参与本场。
- 整房关闭（非持久/局域网房主从面板离开房间、服务器关房）：本场没有终局，双方各自承担本局已下底注，不结算、不退款；客户端收到关房通知就停止，不得自行判定胜负。
- 持久房间单人离开（房间还在）：留下的人等权威结算，约 20 秒心跳沉默后离开方判负、底池归留下的人。两人都走了玩家列表才空，对局不会被结算；权威在最后一次活动满 20 秒后允许新的房主直接开新局，旧底池按整房关闭处理，记录随 TTL 回收。
- 不做断线重连、不做托管；房间服务器超时移除玩家等同离开。

## 5. 客户端与界面

- 左轮大厅新增“联机 1v1”入口：
  - 不在房间：按钮置灰，提示先到“设置 → 联机”建房/加入。
  - 在房间且 `caps` 含 `game`：可创建/加入牌桌。
- 房主大厅：设置区 + “创建牌桌”；创建后等客人。
- 客人大厅：显示房主牌桌设置 + “加入牌桌”；金币不足时禁用。
- 牌桌页：
  - 顶部显示双方昵称/头像、命数、比分、底池。
  - 装弹阶段只有房主能点弹孔/随机装弹；客人显示等待。
  - 自己回合显示“开枪 / 让枪 · 付 X”；对手回合显示等待。
  - 回让后按钮置灰，提示“对手回让，你必须开枪”。
  - 结算卡显示净收/净付、底池、累计底注、让枪费。
- 关闭扩展大窗口 = 离开牌桌；面板里重新打开会回到大厅（在线对局不恢复）。

## 6. 金币与账本

- 新增薄钱包动作 `online-wallet`（仍在 `extensions/roulette/server.js`，单文件 ≤600 行）：
  - `kind:'stake'`：`{matchId, handId, amount}`；按 `matchId+局号` 幂等扣本局底注。
  - `kind:'fee'`：`{matchId, id, amount}`；`id` 用权威事件的 `rev`，按 `matchId+rev` 幂等扣让枪费。
  - `kind:'settle'`：`{matchId, winner:'you'|'them', pot}`；按 `matchId` 幂等，赢家 `earn(pot)`，输家不入账；净额由客户端展示。
  - `kind:'refund'`：开局前取消时按本机账本退回该场已扣底注与让枪费。
  - 账本只存在本机 `extData.online`，`view` 不回吐；对手余额不可见。
- 账本只记本机玩家的收支；对手的余额和账本不可见、不可验证。
- 反作弊边界：朋友局信任模型。房主/公网权威可以保证牌局状态公平，但改不了对方存档；客户端改存档或拒付无法被远端强制。

## 7. 部署

### 7.1 局域网

桌面版内置 Node 房间服务器（`apps/desktop/lib/room-server.js`），`authority:"host"`；无需额外进程。

### 7.2 公网

- 房间服务器：现有 Rust 单二进制，新增 `--authority-url http://127.0.0.1:47825/v1/game --authority-secret <token>`（必须是完整接口地址，带上 `/v1/game`）；房间状态里 `authority` 标明 `"server"`。
- 持久房间（默认）和 `--no-persistent` 都支持联机：持久房间没有房间生命周期上的房主，左轮按加入顺序第一位当开局人；`--no-persistent` 由第一位玩家当房主，离开即关房。
- 权威进程：`node apps/room-authority/authority.mjs --listen 127.0.0.1 --port 47825 --secret <token>`；systemd 与房间服务器同机。
- 公网部署文档补充两个 unit、secret 生成和健康检查；不改变房间服务器的 TLS/反代方式。

## 8. 协议与安全

- 客户端永远拿不到 `bullets` 数组；快照只含 `bulletsLeft`、`chamber`、`fired`、`lastEvent`。
- 服务端从 token 推导 `from`；拒绝客户端自带 `from`/`playerId`。
- 事件大小、深度、字符串长度、速率全部限制；非法包返回 400，不进入队列。
- 公网权威进程只监听 127.0.0.1，共享密钥 32 字节随机；密钥错误返回 401。
- 房间服务器不解析牌局内容，只做白名单和长度校验；牌局合法性由权威/房主客户端负责。

## 9. 实施阶段

1. 共享规则模块 `src/extensions/roulette/online.js` + 单测（双座位状态机、让枪/回让、结算）。
2. Node 房间服务器 `/v1/room/game` + `gameEvents` + 限速/大小校验 + 单测。
3. Rust 房间服务器同协议 + 权威转发 + 集成测试。
4. 桌面桥：`room-client` / `room-manager` / IPC / preload / `app.room` + 单测。
5. 扩展在线大厅与牌桌 UI、钱包动作 + 单测。
6. 公网权威进程 `apps/room-authority/` + 与 Rust 的联调测试。
7. 虚拟机双客户端真机验收（局域网房主模式 + 本机模拟公网权威模式）。
8. 独立测试 agent 验收后再提交；registry/打包/发版仍需用户同意。

## 10. 验收硬门槛

- 双客户端能完成一整场 1v1（单局与三局两胜各一场），比分、命数、底池、净额一致。
- 让枪费进底池；回让后先让者必须开枪；客户端和服务端都拒绝继续让枪。
- 任何广播/快照都不含 `bullets`；抓包检查通过。
- 旧 `seq`、重复动作、伪造 `from`、超大 `data`、超速请求都被拒绝或幂等丢弃。
- 房主关窗、客人关窗、开局前取消三种路径的金币账本与文案一致。
- 公网模式关掉房主客户端后对局仍能继续（权威在服务器）；局域网模式房主关窗即结束。
- Node 与 Rust 房间服务器各跑一遍同一套协议测试。
